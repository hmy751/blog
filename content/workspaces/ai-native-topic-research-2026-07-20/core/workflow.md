# Workflow

이 문서는 `src`를 읽고 작업하는 전체 흐름을 소유한다. review는 이 흐름의 한 단계이며, review 결과만으로 현재 그림이나 원고를 바꾸지 않는다.

## 1. 재진입

1. [active-state/index.md](../active-state/index.md)에서 전체 그림과 단 하나의 현재 cursor를 확인한다.
2. cursor가 가리키는 가지를 읽고, 그 가지가 연결한 `active-state` 상세 파일이 있으면 연다.
3. 현재 작업에 필요한 [criteria.md](./criteria.md)의 판단축만 고른다.
4. 대상 [src](../src/README.md)를 읽는다.
5. `active-state`가 현재 판단에 필요하다고 연결한 material·결정 기록은 표시된 역할과 범위만 연다.
6. 원천은 사실·장면·인과가 쟁점이 될 때 [sources/index.md](../sources/index.md)에서 필요한 직접 원천만 연다.
7. 그 밖의 과거 판단 이유가 필요한 경우에만 [process](../process/README.md)로 내려간다.

`process` 전체나 모든 원천을 재진입 기본 context로 사용하지 않는다.

## 2. 작업 범위 정하기

작업 전에 무엇을 바꾸려는지 다음 중에서 구분한다.

- 사실 오류
- 문장과 국소 표현
- 대표 장면
- 글의 구조
- 글의 중심
- 사용자의 경험·해석

이 구분은 수정의 크기를 재기 위한 등급이 아니라, 누가 결정할 수 있는지 확인하기 위한 것이다.

- 명백한 사실 오류는 직접 원천으로 확인해 고친 뒤 사용자에게 보고할 수 있다.
- 사실 교정이 장면의 역할이나 중심 해석을 바꾸면 수정 전에 사용자와 상의한다.
- 대표 장면, 큰 구조, 글의 중심, 사용자의 경험·해석 변경은 사용자와 상의한다.
- 오탈자, 깨진 링크, 의미를 바꾸지 않는 기계적 정리는 main이 처리할 수 있다.

## 3. `src` 작업과 이전 결과물

`src`에는 현재 수정할 최신 산출물만 둔다.

- 같은 판단 안의 작은 편집은 현재 파일에 반영한다.
- 새 결과물이 현재본이 되면 이전 결과물은 관련된 `process` 과정 안의 적절한 위치로 옮기고, `src`에는 최신본만 남긴다.
- `process`의 내부 분류는 실제 작업 묶음에 맞춰 러프하게 둔다. 모든 편집본을 보존하거나 공통 version 체계를 강제하지 않는다.

`src`는 이 작업 단위의 작업 원본이다. 발행 후보를 repo의 공식 공개 전 단계로 올릴 때는 선택한 원고를 `content/drafts/`로 승격하고 repo의 prepublish 검사를 실행한다.

## 4. Review 목적과 입력을 나누기

입력을 얼마나 가렸는지만으로 review 역할을 정하지 않는다. 먼저 이번 review가 결과물을 개선하려는지, 처음 읽히는 모습을 보려는지, 사실을 확인하려는지 정한다.

### 결과물을 개선하는 review

목적은 현재 결과의 등급을 붙이는 데서 끝나지 않고, 무엇을 기준으로 보면 더 나은 결과가 되는지 찾아 다음 수정과 다음 판별을 가능하게 하는 것이다.

입력:

- 대상 `src` 결과물
- 이번 결과가 도달하려는 최소 목표와 독자
- [sources/index.md](../sources/index.md)에서 고른 직접 원천

main은 현재 쟁점에 필요한 최소 원천 묶음을 먼저 제공한다. reviewer는 그 묶음으로 개선 기준을 세우기 어렵거나 main이 놓친 material을 독립적으로 확인할 수 없다고 판단하면, 부족한 원천의 역할을 밝히고 `sources/index.md`에서 추가 직접 원천을 스스로 고르거나 요청할 수 있다. 추가할 때도 `active-state`와 `process`를 우회 입력으로 사용하지 않는다.

기본적으로 넣지 않는 입력:

- `active-state`
- 이 작업의 `process`
- 이전 원고와 review
- main이 채택하려는 방향이나 예상 판정

직접 원천은 결과물의 사실 확인만을 위한 것이 아니다. 원천과 결과를 대조해 빠진 동기, 장면, 대비, 판단 논리, 아직 쓰지 않은 가능성을 발견하는 데도 사용한다. 다만 원천의 모든 내용을 넣는 것을 품질로 삼지 않는다.

reviewer는 다음을 구분해 보고한다.

1. 실제로 본 입력 경계
2. 이 결과를 더 낫게 판단할 개선 기준 후보와 각 기준이 필요한 이유
3. 그 기준으로 본 현재 결과의 강점과 가장 큰 간극
4. 통과가 아니라면 무엇이 채워져야 하는지
5. 이번 결과를 고칠 제안과 이후에도 반복할 기준 후보

reviewer는 문제 정의나 중심 자체를 다시 열 수 있다. 다만 reviewer가 제안한 기준과 중심 변경은 새 관찰이며 자동 채택되지 않는다.

### 원고만 읽히는지 보는 review

원고만 주는 검토는 처음 보는 독자가 무엇을 이해하고 어디서 막히는지 확인할 때만 사용한다.

- 원고 밖의 material이나 직접 원천을 보지 않았다는 입력 경계를 적는다.
- 독자 진입, 중심의 가시성, 내부 맥락 의존, 반복과 흐름을 관찰한다.
- 원천에 있는데 빠진 material, 사실 정확성, 현재 합의까지 판정한 결과처럼 확대하지 않는다.
- 이 검토 하나의 수정 강도나 통과 판정을 전체 개선 상태로 사용하지 않는다.

### 사실을 보는 verifier

- 검증할 주장과 직접 원천 접근점을 제공한다.
- verifier가 필요한 원천 범위와 판정을 정한다.
- 예상 결론이나 main의 채택 방향을 제공하지 않는다.

### 맥락을 포함한 편집·조언

현재 중심을 지키며 대안을 만드는 작업자는 `active-state`, 필요한 `criteria`, 대상 `src`, 필요한 원천을 읽는다. 과거 `process` 전체는 자동 입력이 아니며, 특정 판단의 이유가 필요할 때만 연다.

## 5. Main의 대조와 조율

독립 결과는 다음 순서로 회수한다.

1. review가 실제로 본 입력과 판정 범위를 확인한다.
2. reviewer가 제안한 개선 기준을 [active-state](../active-state/index.md), [criteria](./criteria.md), 사용자 판단과 대조한다.
3. 기준 후보가 글의 중심, 사용자의 경험·해석, 현재 전체 그림을 바꾸면 사용자와 먼저 상의한다.
4. 선택한 개선 기준으로 review의 관찰과 통과 조건을 다시 읽는다.
5. 사실 충돌은 필요한 직접 원천으로 확인한다.
6. 제안을 다음처럼 구분한다.
   - 현재 그림 안에서 사실을 바로잡는 제안
   - 현재 중심을 유지하며 표현을 고치는 제안
   - 대표 장면이나 구조를 바꾸는 제안
   - 글의 중심이나 사용자의 해석을 바꾸는 제안
   - 이번 결과물만 고칠 조건과 이후에도 반복할 기준
7. 사실 오류는 교정 후 보고한다. 장면·큰 구조·중심·사용자 해석은 사용자와 상의한다.
8. 채택·조정·기각·보류와 이유를 해당 `process` cycle에 남긴다.
9. 현재 함께 작업할 판단이 바뀌면 `active-state`를 갱신한다.
10. 여러 cycle에 반복할 기준으로 합의한 경우에만 `core/criteria.md`를 갱신한다.

반복해서 같은 문제가 나타났다는 사실은 현재 중심을 자동 폐기하지 않는다. 다만 기존 중심이나 장면을 다시 열어야 한다는 신호로 올릴 수 있다.

## 6. 상태 갱신

`active-state/index.md`에는 현재 단계의 요약이 아니라 작업 전체의 생각 구조를 최신 상태의 트리로 유지한다. 완료된 큰 가지도 현재 위치와 중심을 이해하는 데 필요하면 현재 결론을 한두 줄로 접어 남긴다.

- 라벨 없음: 현재 함께 작업할 기본 그림
- `[열림]`: 지금 판단하거나 시험할 질문
- `[보류: 다시 볼 조건]`: 현재 작업을 막지 않으며 조건이 충족될 때 다시 볼 질문

현재 판단이 커지면 다음처럼 나눈다.

- `active-state/index.md`: 전체 지도에서 그 가지가 맡는 역할, 현재 결론, 상세 링크
- `active-state/<branch>.md`: 현재도 유효한 판단의 확대판
- `process/`: 그 판단이 만들어지고 바뀐 논의, review, 이전 상태

`process`는 커진 현재 판단을 밀어 넣는 overflow가 아니다. 완료된 가지의 상세가 process에 있더라도, active-state에는 그 가지의 현재 결론을 남긴다. 링크를 열지 않아도 무엇을 거쳤고 무엇이 유지되며 현재 위치와 어떻게 이어지는지 알 수 있어야 한다.

진행 cursor는 `active-state/index.md`에만 정확히 하나 둔다. 하위 상세 파일에는 별도 cursor를 만들지 않는다.

상태를 바꿀 때는 다음을 함께 확인한다.

- 현재 그림 자체가 바뀌었는가, 아니면 review 관찰만 추가됐는가?
- 완료된 큰 가지를 지워 전체 그림이나 합의의 계보를 잃게 만들지는 않았는가?
- 현재도 유효한 판단을 과거 과정과 함께 `process`로 내려버리지는 않았는가?
- 열린 질문이 무엇인지 한 문장으로 말할 수 있는가?
- 보류를 다시 열 조건이 적혀 있는가?
- 지난 세부 과정은 `process`로 연결하고, 현재 결론은 지도에 남겼는가?
- `` `*-> 지금*` ``이 정확히 하나인가?

## 7. 이 workflow를 고칠 때

이 workflow는 불변 규칙이 아니다. 역할이나 권한 경계가 실제 작업과 맞지 않으면 사용자와 논의해 현재 문서를 고치고, 바뀐 이유와 이전 방식은 `process/context-structure/`에 남긴다.
