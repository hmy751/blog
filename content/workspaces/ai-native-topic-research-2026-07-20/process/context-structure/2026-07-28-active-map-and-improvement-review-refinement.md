# 전체 생각지도와 개선 review를 첫 운용 뒤 보정한 이유

## 배경

첫 context 층위 정리에서는 `active-state`를 최신 상태의 뼈대로 두고, 과거 과정은 `process`로 내리며, 독립 review는 결과물만 보게 하는 방향을 먼저 구현했다. 구조를 실제 Current 글 재작성에 사용해 보니 두 의도가 지나치게 좁게 적용됐다.

- `최신 상태`가 작업 전체에서 각 가지의 최신 판단이 아니라 직전 단계와 현재 산출물만 뜻하는 것으로 축소됐다.
- `독립 review`가 기존 판단에 앵커링되지 않는 검토가 아니라, 원고와 고정 질문만 보고 제한된 읽힘을 확인하는 절차로 축소됐다.

그 결과 파일은 정리됐지만, 새 session이 왜 이 작업을 시작했고 무엇을 이미 거쳤으며 어떤 판단이 지금까지 이어지는지 충분히 복구하지 못했다. review도 원천에 남은 재료와 현재 결과의 차이를 발견해 다음 개선 기준을 세우지 못했다.

## 첫 운용에서 드러난 문제

### 완료된 큰 가지가 지도에서 사라졌다

초기 active-state는 현재 다섯 원고와 직전 review 상태를 중심으로 압축됐다. 조사, 후보 형성, 첫 shaping, 사용자와 다시 맞춘 중심처럼 이미 완료됐지만 현재 원고의 의미를 이해하는 데 필요한 가지가 보이지 않았다.

새 session은 첫 shaping에 글의 동기와 사용자 판단이 이미 펼쳐져 있다는 사실을 모르고 Material 단계가 생략됐다고 진단했다. 이것은 과거 파일을 전부 읽지 않아서 생긴 문제가 아니라, active-state가 그 과정의 현재 결론과 역할을 지도에 남기지 않았기 때문에 생긴 문제였다.

### 링크가 지도 내용을 대신했다

세부 내용은 process 링크로 접을 수 있지만, 링크만 남기면 사용자는 무엇이 합의됐고 그것이 현재 위치와 어떻게 이어지는지 다시 열어 추론해야 한다. 이는 `current`를 만들었던 원래 문제를 새 구조에서 반복한다.

### Current 재작성의 검증 범위가 완료 판정으로 확대됐다

Current 재작성은 정한 장면, 사실 범위, 공개 경계를 기준으로 shaping·evidence·texture 검토를 통과했다. 마지막 독립 검토는 현재 원고와 고정 질문만 받고 `light edit` 수준의 제안을 남겼다.

그러나 사용자 검토에서는 왜 `current`를 만들었는지, 해커톤 전체 맥락에서 어떤 역할을 했는지, 글쓴이가 무엇을 보고 어떤 판단을 했는지가 충분히 살아 있지 않다는 문제가 확인됐다. 당시 검토는 제공받지 않은 직접 원천과 기존 material의 누락을 판정할 수 없었는데도, 그 제한된 결과가 작업 완료에 가까운 신호로 사용됐다.

### 입력 격리만으로는 개선 역할이 생기지 않았다

과거 process와 기존 판정을 주지 않는 것은 reviewer의 독립성을 지키는 데 필요하다. 하지만 결과물만 주고 main이 미리 정한 질문에 답하게 하면 reviewer는 그 질문의 범위 안에서만 잘 작동한다.

개선 review에는 원천과 결과를 대조해 무엇이 빠졌는지 보고, 더 나은 결과를 판단할 기준과 통과 조건을 제안하는 역할이 필요하다. 원천을 제공한다는 말은 원천의 내용을 모두 원고에 넣으라는 뜻이 아니라, 현재 결과가 어떤 가능성과 판단 재료를 사용하지 못했는지 독립적으로 볼 근거를 준다는 뜻이다.

## 참고한 작동 원리

AX 마이리얼트립 작업의 `context/current.md`는 현재 단계만 보여 주는 상태 보고서가 아니었다. 요구사항, 조사와 문제 정의, 해결안 비교, 구현과 검증, 제출까지 전체 작업을 낮은 해상도의 트리로 두고 그 안에 현재 cursor 하나를 표시했다. 완료된 가지도 현재 위치를 이해하는 데 필요한 최신 결론은 남았다.

같은 작업의 `context/core/loop.md`에서는 판별자가 목표·직접 원천·결과를 보고 평가축과 미통과 조건을 제안하고, 사용자가 어떤 축을 채택할지 정했다. 결과물 수정과 반복 기준 갱신도 같은 결정으로 뭉치지 않았다.

이번 보정은 그 파일 형식을 복제하지 않는다. 다음 두 작동 원리만 현재 workspace의 층위에 맞게 가져온다.

1. active-state는 전체 생각 구조와 현재 위치를 한 화면에서 맞추는 지도다.
2. 독립 reviewer는 기존 결론을 모르는 대신, 결과와 직접 원천에서 개선 기준을 제안할 수 있어야 한다.

## 결정

### Active-state는 작업 전체의 최신 지도다

`active-state/index.md`는 현재 단계의 요약이 아니라 작업 전체 생각 구조의 최신 저해상도 지도다.

- 작업을 시작한 이유, 조사와 판단의 큰 가지, 현재 산출물, 열린 질문과 다음 방향을 함께 둔다.
- 완료된 큰 가지도 현재 위치와 중심을 이해하는 데 필요하면 현재 결론을 한두 줄로 접어 남긴다.
- `최신`은 현재 단계만 보존한다는 뜻이 아니라, 전체 지도 안에서 각 가지의 현재 해석을 유지한다는 뜻이다.
- 링크를 열지 않아도 무엇을 거쳤고 무엇이 지금 유지되며 현재 위치와 어떻게 이어지는지 알 수 있어야 한다.
- `## 현재 지도`라는 사람과 AI의 sync 지점은 유지한다. 트리의 첫 가지와 골격은 현재 그림을 더는 제대로 담지 못할 때 사용자와 맞춘 뒤 바꿀 수 있다.
- 진행 cursor는 `active-state/index.md`에 정확히 하나만 둔다.

### 커진 현재 판단과 지난 과정의 위치를 나눈다

현재도 유효한 판단이 한두 줄을 넘어가면 `active-state/<branch>.md`로 나눈다. `index.md`에는 그 가지의 역할, 현재 결론, 상세 링크를 남긴다.

`process`는 커진 현재 판단을 밀어 넣는 overflow가 아니다. 판단이 만들어진 논의, review, 이전 상태, 바뀐 이유를 보존한다. 완료된 가지의 상세가 process에 있더라도 active-state에는 현재 결론이 남는다.

### 상태어는 예외만 표시한다

- 라벨 없음: 지금 함께 작업할 기본 그림
- `[열림]`: 지금 판단하거나 시험할 질문
- `[보류: 다시 볼 조건]`: 현재 작업을 막지 않으며 조건이 충족되면 다시 볼 질문

라벨 없는 판단은 영구 불변이 아니다. 독립 review나 main의 제안도 자동으로 현재 그림이 되지 않는다. 중요한 변화는 사용자와 맞춘 뒤 갱신한다.

### 개선 review는 목적·원천·산출 계약으로 정의한다

결과물을 개선하는 review에는 다음을 준다.

- 대상 결과물
- 이번 결과가 도달하려는 최소 목표와 독자
- `sources`에서 선별한 직접 원천

기본적으로 다음은 주지 않는다.

- `active-state`
- 작성 `process`
- 이전 원고와 review
- main이 원하는 답이나 예상 판정

reviewer는 다음을 보고한다.

1. 실제로 본 입력 경계
2. 더 나은 결과를 판단할 개선 기준 후보와 그 이유
3. 그 기준으로 본 현재 결과의 강점과 가장 큰 간극
4. 미통과라면 무엇이 채워져야 하는지
5. 이번 결과를 고칠 제안과 이후에도 반복할 기준 후보

main은 현재 쟁점에 필요한 최소 원천 묶음을 먼저 제공하되 그 선택도 정답으로 고정하지 않는다. reviewer는 제공된 묶음이 부족하면 부족한 원천의 역할을 밝히고 `sources/index.md`에서 추가 직접 원천을 고르거나 요청할 수 있다. 이때도 `active-state`와 작성 process를 우회 입력으로 사용하지 않는다.

원고만 제공하는 검토는 없애지 않는다. 다만 처음 보는 독자가 무엇을 이해하고 어디에서 막히는지 보는 제한된 관찰로 사용하며, 원천에 남은 material, 사실 정확성, 전체 개선 상태까지 판정한 결과로 확대하지 않는다. 사실 검증은 직접 원천을 보는 verifier가 별도로 맡는다.

### Main이 개선 기준과 변경 층위를 조율한다

reviewer가 제안한 기준은 새 관찰이지 새 규칙이 아니다. main은 이를 현재 전체 지도, workspace criteria, 사용자 판단과 대조하고 다음을 분리한다.

- 현재 결과물만 고칠 조건
- 현재 글의 장면·구조·중심을 바꿀 제안
- 사용자의 경험·해석을 바꿀 제안
- 여러 cycle에 반복할 기준 후보

명백한 사실 오류는 원천으로 확인해 수정하고 사용자에게 보고한다. 대표 장면, 큰 구조, 글의 중심, 사용자의 경험·해석은 사용자와 먼저 상의한다. 여러 cycle에 반복할 기준으로 합의한 경우에만 `core/criteria.md`를 갱신한다.

## Current 재작성의 현재 판정

`src/current-active-state-operation.md`는 가장 최근 작업 시도지만 사용자에게 수용된 완성본이 아니다. 당시 검증은 정한 구조와 사실·공개 경계를 확인한 기록으로 보존하되, 글의 동기와 전체 맥락까지 충분히 살렸다는 판정으로 사용하지 않는다.

다음 단계는 현재 원고와 선별한 직접 원천을 개선 reviewer에게 주어 기준·간극·통과 조건을 제안받고, main과 사용자가 부분 수정인지 구조 재개방인지 조율하는 것이다.

## 적용하지 않는 것

- 모든 과거 과정을 active-state에 다시 넣지 않는다.
- active-state를 세부 상태표나 변하지 않는 명세로 만들지 않는다.
- 모든 판단에 상태 라벨을 붙이지 않는다.
- 직접 원천의 모든 내용을 원고에 넣는 것을 개선 기준으로 삼지 않는다.
- reviewer의 기준, 판정, 수정안을 `src`, `active-state`, `core`에 자동 반영하지 않는다.
- workspace의 이 review 계약을 repo의 모든 글과 모든 reviewer에게 자동 확대하지 않는다.

## 후속 확인

- 새 session이 `active-state/index.md`와 현재 가지 하나만 읽고도 작업의 출발점, 완료된 큰 가지, 현재 중심, 다음 판단을 설명할 수 있는가
- 링크를 열지 않아도 지도 자체가 합의와 현재 위치를 보여 주는가
- 개선 reviewer가 원천을 coverage checklist로 쓰지 않고 빠진 동기·장면·판단 논리를 발견하는가
- main이 이번 결과물 수정과 반복 기준 갱신을 분리하는가
- Current의 다음 수정 뒤에도 중심 material이 살아 있고 독립성이 유지되는가
