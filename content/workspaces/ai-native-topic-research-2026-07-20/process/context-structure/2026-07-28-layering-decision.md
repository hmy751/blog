# AI-native 0720 작업의 context 층위를 다시 나눈 이유

## 출발점

`ai-native-topic-research-2026-07-20` 작업은 두 위치에 나뉘어 있었다.

- `content/backlog/ai-native-topic-research-2026-07-20`: 기준, 후보, 조사와 shaping 과정
- `content/drafts/ai-native-topic-research-2026-07-20`: 여러 세대의 다섯 원고

작업이 길어지며 active-state, 기준, 후보 카드, review, main 판정, 여러 draft version을 함께 읽어야 재진입할 수 있게 됐다. 자료가 없는 문제가 아니라, 서로 다른 역할의 자료가 같은 context에 들어오면서 무엇이 현재 그림이고 무엇이 과거 과정인지 다시 추론해야 하는 문제가 생겼다.

이번 정리는 파일을 보기 좋게 옮기는 것보다 다음 세션과 다른 AI가 전체 그림을 놓치지 않으면서도, 모든 과거 정보에 묶이지 않게 하는 데 목적이 있다.

## 논의에서 확인한 실패 양상

### 과거 자료를 많이 준다고 판단이 나아지지 않았다

reviewer에게 backlog까지 제공했을 때, 이전 기준과 설명이 판단을 돕기보다 특정 문제에 앵커링시키는 경우가 있었다. 이미 고쳐진 사실이나 과거의 오독이 현재 원고를 보는 강한 프레임이 되면, 좋은 변화를 실패의 연장으로 읽기도 했다.

따라서 모든 역할이 전체 backlog를 읽는 방식을 기본값으로 둘 수 없었다.

### 결과물만 본 판별자도 기존 합의를 알 수 없었다

반대로 원고만 본 독립 판별은 기존 합의나 사용자가 직접 맞춘 의미를 모른다. 이것은 원고 자체의 읽힘을 독립적으로 보는 데는 유효하지만, 그 제안을 곧바로 현재 기준이나 수정 명령으로 올리면 이미 합의한 중심을 뜻하지 않게 되돌릴 수 있다.

2026-07-28의 draft-only blind review는 다섯 편 모두 `partial rewrite`로 판정했지만, 사실·source 검증과 main의 조율을 포함하지 않았다. 이 판정은 새 관찰이지 사용자 합의가 아니다.

### Main의 회수 단계가 빠지면 두 입력 방식의 단점이 그대로 반영됐다

문제는 reviewer에게 맥락을 얼마나 주느냐만이 아니었다. 독립 결과를 받은 main이 현재 그림과 대조하고, 필요한 사실만 원천으로 확인하고, 제안이 장면·중심·사용자 해석 중 무엇을 바꾸는지 구분하는 단계가 필요했다.

독립 판별은 차이를 만드는 역할이고, main은 그 차이를 현재 작업에 어떻게 사용할지 조율하는 역할이다. 둘은 같은 판단자가 아니다.

### 사실 교정과 후보·장면 판정을 분리해야 했다

수치, 실제 구현 여부, 사건 순서처럼 명백히 틀린 사실은 고쳐야 한다. 하지만 사실 하나가 틀렸다는 이유만으로 그 후보의 가치, 장면 전체, 사용자의 경험 해석까지 틀렸다고 판정할 수는 없다.

반대로 사실 교정이 글의 인과나 중심을 실제로 바꾸는 경우에는 기계적인 수정으로 끝낼 수 없다. 무엇이 바뀌는지 사용자와 다시 맞춰야 한다.

### `열림/닫힘`만으로는 변화의 농도를 표현하지 못했다

일부 판단은 지금 작업의 기본 전제지만 나중에 다시 열릴 수 있다. 일부는 아직 결정되지 않았지만 현재 작업을 막지 않는다. 일부는 과거에 완료됐지만 현재 context에 계속 노출할 필요가 없다.

모든 판단을 `닫힘`으로 표시하면 불변처럼 읽히고, 모든 항목에 상태를 붙이면 전체 그림보다 상태 관리표가 앞선다. 그래서 라벨이 없는 항목을 현재 함께 작업할 기본 그림으로 두고, 예외인 `[열림]`과 `[보류: 다시 볼 조건]`만 표시하기로 했다.

## Current 사례에서 배운 것

참고한 AX 마이리얼트립 작업의 `context/current.md`는 좁은 active context packet만을 위한 문서가 아니었다. 전체 프로젝트를 낮은 해상도의 트리로 보여 주고, 그 안에서 현재 한 점을 표시해 사용자와 AI가 같은 그림을 보게 하는 scaffolding이었다.

가져온 핵심은 다음과 같다.

- 전체 생애주기를 낮은 해상도의 트리로 보여 준다.
- 현재 cursor는 하나만 둔다.
- 긴 설명과 세부 근거는 역할이 적힌 링크로 접는다.
- 현재 상태는 덮어쓰고, 바뀐 이유와 이전 상태는 process에 보존한다.
- 한 session의 최근 작업이나 한 단계의 문제를 전체 프로젝트로 오인하지 않게 한다.

반면 AX `current.md`의 모든 단계와 실행 scaffolding을 그대로 복제하지는 않았다. 이번 작업에는 이미 repo 공통 editorial 규칙과 별도 process가 있고, 이를 active-state에 다시 넣으면 같은 비대화가 반복되기 때문이다.

## 검토한 단독 해법과 한계

### Sources를 정확히 두는 것

직접 원천과 파생 해석을 나누는 데 필요하지만, 어떤 역할이 언제 무엇을 읽고 누가 해석을 갱신하는지까지 정하지는 못한다.

### Criteria를 고정하는 것

반복 판단축을 복구하는 데 필요하지만, 현재 장면과 중심을 모두 기준으로 만들면 과거 판단이 새 가능성을 닫는다. criteria 자체도 작업을 통해 수정될 수 있다.

### Active-state 하나로 관리하는 것

현재 그림을 복구하는 데 필요하지만, review 입력과 main의 회수 권한을 정하지 않으면 모든 역할에 같은 context가 다시 들어간다.

### 독립 판별자에게 전체 맥락 또는 결과물만 주는 것

두 방식 모두 역할에 따라 쓸 수 있지만 하나를 전체 기본값으로 만들 수 없다. 원고 자체를 보는 blind review와 사실을 확인하는 verifier, 현재 중심 안에서 대안을 만드는 editor는 서로 다른 입력이 필요하다.

결론적으로 단일 파일이나 상태어가 아니라 층위와 workflow의 조합이 필요했다.

## 결정한 구조

### `AGENTS.md`

작업 단위의 입구다. 역할별 첫 read path와 층위별 소유권, 사용자와 상의해야 하는 변경 경계를 안내한다. 현재 후보나 cursor의 세부 내용은 소유하지 않는다.

### `core/`

여러 cycle에서 반복해서 사용할 운영 계약을 둔다.

- `workflow.md`: 재진입, `src` 작업, review 입력, main 조율, active-state 갱신
- `criteria.md`: 이 작업에서 반복해서 사용하는 판단축

`core`는 영구 불변이 아니다. active-state보다 덜 자주 바뀌지만 실제 작업과 맞지 않으면 사용자와 논의해 고치고, 변경 이유는 process에 남긴다.

### `active-state/`

현재 전체 그림과 현재 한 점을 트리로 보여 준다.

- 라벨 없는 노드는 현재 함께 작업할 기본 그림이다.
- `[열림]`은 지금 판단하거나 시험할 질문이다.
- `[보류: 다시 볼 조건]`은 현재 작업을 막지 않는 질문이다.
- review가 완료됐다는 사실과 review 결론을 채택했다는 판단을 구분한다.
- `` `*-> 지금*` ``은 정확히 하나만 둔다.

과거 cycle의 설명, 긴 후보 카드, review별 세부 제안은 active-state에서 내려 `process`로 보낸다.

### `sources/`

현재 작업에서 실제로 다시 열 직접 원천의 링크와 짧은 설명, 각 원천이 지원하는 범위를 둔다.

원 프로젝트의 `context/process`나 `docs/decisions`는 이름이 process여도 당시 사건을 기록한 직접 원천이면 sources에 연결한다. 반대로 이 0720 작업에서 만든 source-check, 후보 해석, review와 adjudication은 파생 과정이므로 이 작업의 `process`에 둔다.

### `process/`

조사, 시도, 후보 형성, shaping, review, main의 채택·조정·기각·보류, 기준 변화와 이전 결과물처럼 작업하며 생긴 것을 러프하게 담는다. 평상시 재진입 필수 context가 아니라 “어떤 과정을 거쳤는가”가 필요할 때 내려가는 층위다.

`process` 자체를 정교한 snapshot archive나 고정된 version 체계로 만들지 않는다. 내부 배치는 실제 작업 묶음을 따라가며, 이전 원고도 그 과정에서 생긴 결과물로 함께 둘 수 있다.

### `src/`

지금 작업할 최신 산출물만 둔다. 이번 정리 시점에는 `public-reshape-v1` 다섯 편이 현재본이다.

새 결과물이 현재본이 되면 이전 결과물은 관련 process 과정 안의 적절한 위치로 옮긴다. 모든 편집본을 보존하거나 공통 version 규칙을 강제하지 않는다.

`src`는 작업 원본이며 repo의 `content/drafts`와 역할이 다르다. 실제 발행 후보를 정하면 선택한 원고를 `content/drafts`로 승격한 뒤 prepublish 흐름에 넣는다.

## 첫 구현 뒤 보정 — process는 snapshot 층위가 아니다

첫 구조에서는 이전 원고를 의미 있는 경계의 `snapshot`으로 설명하고 별도 보존 규칙까지 두려 했다. 결과물을 본 뒤 사용자는 `process`의 본래 역할이 snapshot 관리가 아니라 과정을 러프하게 담고 보는 데 있다고 다시 짚었다.

이에 따라 별도의 최상위 `snapshots/` 층위를 추가하지 않고 다음처럼 단순화했다.

- `process`는 조사, 시도, review, 판단과 그 과정에서 생긴 이전 결과물을 함께 담을 수 있다.
- 과정 안의 `drafts/` 같은 하위 폴더는 현재 자료를 찾기 위한 실용적인 정리일 뿐, 모든 작업에 강제하는 구조가 아니다.
- 엄격하게 유지할 경계는 `src`에 최신 결과물만 둔다는 점이다.
- 이전 결과물의 세부 보존 단위는 필요할 때 정하며, 일반 workflow로 미리 고정하지 않는다.

## Review와 main의 권한 경계

### Review

- 원고 자체를 보는 독립 review는 원고와 질문만 보고, 입력 경계를 보고서에 적는다.
- 사실 verifier는 주장과 직접 원천에서 시작하고 예상 결론을 받지 않는다.
- 현재 중심 안에서 대안을 만드는 editor는 active-state와 필요한 criteria, 대상 원고와 필요한 원천을 본다.
- 어떤 review도 `src`나 `active-state`를 직접 갱신하지 않는다.

### Main

- review가 본 입력과 판정 범위를 확인한다.
- review 결과를 현재 그림과 대조한다.
- 사실 충돌에 필요한 직접 원천만 연다.
- 명백한 사실 오류는 확인 후 수정할 수 있지만 사용자에게 무엇을 고쳤는지 보고한다.
- 사실 교정이 장면이나 중심을 바꾸면 수정 전에 사용자와 상의한다.
- 대표 장면, 큰 구조, 글의 중심, 사용자의 경험·해석 변경은 사용자와 상의한다.
- 채택·조정·기각·보류와 이유를 process에 남긴다.
- 실제 합의로 현재 그림이 바뀐 경우에만 active-state를 갱신한다.

## 이 논의에서 유지한 Current 글의 현재 경계

- `current`는 전체적으로 도움이 된 sync scaffolding이었고 지금도 유사한 active-state 방식을 사용한다.
- Q1~Q5 오류는 한계와 회수 과정의 자료이지 `current`가 전체적으로 실패했다는 증거가 아니다.
- Q1~Q5 회수는 사용자 정정, current 지도, process와 직접 원천이 함께 작동한 결과다.
- 다만 지금 초안의 대표 장면이 이 중심을 가장 잘 보여 주는지는 다시 열려 있다.

즉 현재 의미를 기본 그림으로 유지하면서 장면은 다시 열 수 있다. 독립 판별에서 같은 문제가 반복된다면 기존 중심을 자동 폐기하는 것이 아니라, 장면이나 중심 중 무엇을 다시 열지 사용자와 판단한다.

## 구현하며 확인하기로 남긴 것

다음은 추상적으로 더 정하지 않고 첫 결과물을 본 뒤 조정하기로 했다.

- 실제 active-state 트리의 깊이와 정보량이 전체 그림을 보기에 맞는가
- `criteria`로 추린 항목 중 active-state나 repo editorial로 옮길 것이 더 있는가
- `[열림]`, `[보류]`가 실제 작업에서 충분한가
- 첫 다음 edit를 한 편으로 시작할지 다섯 편을 함께 볼지
- Current 글의 대표 장면을 유지할지 교체할지

이 항목들은 첫 구조가 틀렸다는 뜻이 아니라, 구조가 실제 context에서 작동하는지 보고 다듬을 대상이다.
