# 새 v1 build record

이 문서는 새 v1 다섯 편을 쓰며 적용한 판단을 보존한다. material report의 `Possible center`, `Missing question`, `Spine hypothesis`, `Recommended stance`는 초안 재료이며 현재 중심을 다시 여는 권위를 갖지 않는다.

후보마다 다음 세 가지를 남긴다.

1. 사용자 sync에서 닫힌 중심
2. main이 초안에서 선택한 장면과 배열
3. 직접 원천과 기존 사실 교정에서 지킨 주장 상한

독립 review 결과와 그에 대한 main 판정은 이 문서에 섞지 않고 각각 `03-independent-review.md`, `04-main-adjudication.md`에 둔다.

## Current / active-state operation

### 닫힌 중심

실제로 도움이 되어 계속 사용하는 active control의 구조를 다룬다. 전체 지도와 현재 판단점, 현재 계약과 history, current와 권위 원천은 서로 다른 역할을 가지며 한 글 안에서 연결된다. Q1~Q5와 terminal event 누락은 효용을 지우는 중심 실패가 아니라 작동 조건과 한계다.

### 선택한 배열

- 현재 contract가 process history 안에 있던 장면에서 시작한다.
- active contract와 history를 분리한 뒤 전체 지도와 단일 cursor가 왜 함께 필요했는지 펼친다.
- Q1~Q5 오독은 current를 읽는 것과 질문의 시간축에 맞게 작동시키는 것이 다르다는 stress test로 둔다.
- terminal event 누락으로 갱신 ownership의 한계를 남긴다.
- 현재 블로그의 `active-state/process` 분리는 이 구조를 지금도 사용하는 짧은 현재형 보강 장면으로만 쓴다.

### 지킨 상한

- Q1~Q5 복구는 사용자 정정, current map, 직접 원천 재접근, 병렬 작업의 최신 결과가 함께 만든 결과다.
- current 활동 수치와 문서 축약 수치를 품질·생산성 지표로 쓰지 않는다.
- terminal event 누락의 직접 원인을 update ownership 하나로 단정하지 않는다.
- current 단독으로 재진입·연속성·생산성이 좋아졌다고 말하지 않는다.

## 독립 판별 / 제3판별자

### 닫힌 중심

별도 AI를 더 부르는 일이 아니라 구현자와 다른 입력·질문·권한을 가진 판단 위치를 만들고, 결과를 main 언어에 흡수하기 전에 별도 상태로 노출한 뒤 원자료와 재실행으로 회수하는 구조를 다룬다.

### 선택한 배열

- 9개 `unittest` test method와 별도 validator·CLI가 통과한 AX checkpoint에서 시작한다.
- test가 같은 세계 안에서 정직하게 통과했음을 설명한다.
- read-only 판별자가 공개 source, 실제 자연어 입력, 적대 조건을 열어 질문의 경계를 바꾼 장면을 둔다.
- 교정 뒤 15개 test method, 별도 validator·CLI, 설치형 자연어 E2E로 같은 checkpoint를 다시 닫는다.
- 판별 결과를 별도 상태로 남기고 main이 원자료·재실행으로 채택하는 회수 구조까지 연결한다.
- 다른 판정 실험은 판별자도 닫힌 입력 밖을 자동 복구하지 못한다는 짧은 경계로만 사용한다.

### 지킨 상한

- 9와 15는 한 runner의 test method 수다. validator, CLI, 설치형 E2E는 숫자 밖의 별도 검증이다.
- test 수 증가를 품질이나 사용자 가치 향상으로 쓰지 않는다.
- 첫 판별자는 무맥락 clean-room 외부 평가자가 아니었다.
- 회귀 판별은 설치 상태와 E2E artifact도 입력으로 받았으므로 제출물 하나의 독립 재현이 아니다.
- 다른 모델, 별도 호출, reviewer 수를 독립성의 충분조건으로 만들지 않는다.

## 제품 흐름을 보존하는 scope control

### 닫힌 중심

`작게`, `안전하게`, `빨리 보이게`라는 압력 아래 불확실하지만 가치가 생기는 핵심보다 완료로 세기 쉬운 대체 결과가 먼저 선택된 장면을 다룬다. 범위를 줄일 때는 구현 폭보다 사용자의 결과와 다음 행동을 만드는 제품 흐름을 먼저 보존한다.

### 선택한 배열

- raw `facts[]`를 화면에 직접 표시하자는 구현 전 제안에서 시작한다.
- 중간 산출물이 제품 출력 자리를 차지한 이유와 빠진 변환을 보여 준다.
- “AI 회피성”은 보편적 성격이 아니라 당시 조건에서 관찰된 선택 압력으로 번역한다.
- 후속 실제 구현의 question → retrieval → grounding/status/evidence → answer → chat 흐름을 correction으로 둔다.
- 자료 변화, 실제 원문 grounding, 실제 route 연결을 확인한 세 test와 사용하지 않는 fact path 제거를 제품행동 강제 장치로 둔다.
- deterministic baseline 제안은 위험을 줄이는 일과 제품 경로 밖으로 옮기는 일의 차이를 보여 주는 짧은 보강으로 쓴다.

### 지킨 상한

- raw `facts[]`와 deterministic product proof는 제안이었지 배포된 실패 결과가 아니다.
- 후속 product-flow 구현은 실제 변경이지만 semantic quality와 사용자 가치 전체를 증명하지 않는다.
- deterministic 구현 자체를 가짜라고 일반화하지 않는다.
- 모든 AI가 surrogate output을 선택한다고 말하지 않는다.

## 생성·주장 판정·후보 수렴의 판단 순서

### 닫힌 중심

AI의 노력이 가능한 가치와 성과를 만드는 일보다 탈락 이유를 찾는 데 먼저 쓰인 문제를 다룬다. 후보와 가능한 가치·성과·새 통제력을 먼저 펼치고, 그동안 개별 주장은 엄격하게 판정하며, 후보 전체의 선택·보류·종료는 충분히 펼친 뒤 수렴에서 결정한다.

### 선택한 배열

- 바로 이 글감 조사에서 작업 cursor를 가치 순위로, 주장 상한을 후보 매력 감점으로 바꾼 재귀적 오류에서 시작한다.
- AX에서 세 문제를 닫기 전에 9개 solution, 3개 output, 8개 state transition을 펼쳐 가능한 결과와 통제력을 비교한 장면을 중심 근거로 둔다.
- 첫 후보판의 A1·A2를 별도 비교 단위로 올린 second pass는 문제 경계와 비교 권한이 달라진 보강 장면으로 둔다.
- 후보를 펼치는 동안에도 주장별 `확인됨`, `불충분`, `모름`, `확인 필요`를 유지하는 방식을 설명한다.
- 명백한 사실·안전·비용·공식 경계는 중간에도 종료하고, 후보 전체의 가치 수렴은 뒤에 둔다는 종료 조건으로 닫는다.
- Cofathon은 rubric을 생성의 씨앗에서 뒤의 비교층으로 내린 짧은 반복 사례로만 쓴다.

### 지킨 상한

- blog research의 조기 수렴 actor는 사용자보다 main AI다.
- AX A1·A2는 첫 후보판에도 이미 있었고 second pass가 처음 발견한 문제가 아니다.
- second pass는 완전히 blind하지 않았고 최종 품질 우월성을 증명하지 않는다.
- Cofathon의 서로 다른 후보 수와 계보를 하나의 성능 개선 수치로 잇지 않는다.
- 사용자가 과거에 현재의 세 단계 원칙을 같은 문장으로 이미 갖고 있었다고 소급하지 않는다.

## AI self-check

### 닫힌 중심

AI가 자기 frame 안에서는 자신의 판단마저 객관적으로 보지 못하고 반복 설명하거나 반대 방향으로 과교정할 때, 자신의 framing·문제 정의·전제·scope·도구 선택·판단축을 검사 대상으로 만드는 일을 다룬다. “더 근본적으로”는 더 추상적인 일반론이 아니라 방금 결과를 만든 결정 위치로 돌아가는 일이라는 문장은 이 중심을 드러내는 발견이다.

### 선택한 배열

- AX에서 한쪽 편향을 교정한 뒤 main이 반대 방향으로 넘어간 장면으로 시작한다.
- 직전 결론이 아니라 그 결론을 만든 판단축·입력 범위·증명 범위를 검사 대상으로 만든다는 문제를 연다.
- assignment 누락은 self-check 질문이 생긴 발생 배경으로 둔다. 폴더 부재를 원자료 부재로 바꾼 전제와 검색 범위를 너무 일찍 닫은 판단을 보여 준다.
- “더 근본적으로”를 더 큰 일반론으로 오독했던 장면에서 자기 판단 위치를 객관화한다는 정의를 회수한다.
- forward bias 반복은 정확한 설명, 다음 행동 변화, 재발 감소가 다른 결과임을 보여 주는 stress test로 둔다.
- 같은 판단 위치가 스스로 빠져나오지 못할 때 자기 판단을 별도 판별 위치에 맡긴다는 연결만 짧게 남긴다.

### 지킨 상한

- assignment의 행동 변화는 정식 self-check 이전의 사용자 정정과 전체 rescan이 함께 만든 결과다.
- AX 복구는 사용자 정정, 넓어진 입력, 두 번째 판별, main 재적용이 함께 만들었다.
- forward-bias 원문에는 사용자의 세 차례 제동이 남아 있으며 전체 반복 횟수로 확대하지 않는다.
- self-check가 행동 안정이나 재발 감소를 만들었다고 말하지 않는다.
- 단순 질문과 첫 정정을 모두 self-check로 올리지 않는다.
- 확인되지 않은 `ai-self-check-fundamental.md`를 원천으로 사용하지 않는다.

## Shaping review와 main 반영

다섯 초안 작성 뒤 report-only shaping review를 세 갈래로 나눠 받았다. reviewer에게는 회수된 중심과 주장 상한을 함께 주되, 중심을 다시 여는 권한은 주지 않았다. main은 각 제안을 현재 중심과 원자료 역할에 대조해 다음처럼 반영했다.

### 공통 판정

- 다섯 편 모두 중심을 다시 잡는 재작성은 필요하지 않았다.
- 새 기준을 추가하지 않았다. 이미 정한 중심이 독자에게 보이도록 heading 층위, 장면 순서, artifact 가시성을 조정했다.
- 방어 문장은 사실 상한을 지키는 데 필요한 범위만 남기고, 같은 뜻의 반복은 줄였다.

### Current

- `원천 / history / active contract / current`의 권한을 네 줄로 펼쳤다.
- 후반의 최근성 편향, 갱신 ownership, 현재 글감 작업의 재현을 하나의 작동 조건·한계 층 아래 배치했다.
- 시간축을 다시 잡는 일과 병렬 작업의 최신 사실을 갱신하는 일을 한 문장 안에서 구분했다.
- `current`를 읽었다는 이유만으로 판단이 자동 교정됐다고 쓰지 않는 상한은 유지했다.

### 독립 판별

- 초반에 이 글이 검증 범위 확대뿐 아니라 판별 출력의 별도 보존과 main의 회수까지 다룬다는 문장을 추가했다.
- test 역할 비교와 설치형 E2E는 질문 경계 변경의 하위 기술 증거로 묶었다.
- 닫힌 입력 밖을 복구하지 못한 두 번째 사례는 별도 판별의 충분조건을 깨는 짧은 하위 반례로 내렸다.
- 9·15 수치, clean-room이 아닌 판별 범위, 회수 권한의 상한은 그대로 보존했다.

### Scope control

- deterministic baseline 진단보다 사용자에게 남겨야 할 상태 변화와 제품 작용을 먼저 배치했다.
- `AI 회피성`이라는 내부 라벨은 공개 문장에서 빼고, 어떤 압력이 완료로 세기 쉬운 결과를 앞세웠는지로 번역했다.
- 세 test를 correction의 직접 증거로 두고 deterministic 제안은 위험 격리와 product proof 대체의 차이를 보여 주는 하위 경계로 압축했다.
- 두 제안을 실제 배포 실패로 바꾸거나 후속 test를 사용자 가치 증명으로 확대하지 않았다.

### 판단 순서

- second pass가 새 문제를 발견한 것이 아니라 기존 차이를 독립 비교 단위로 올리고 판단 권한을 바꾼 일임을 명시했다.
- 세 output이 만든 사용자 판단과 상태 변화의 차이를 공개 가능한 작은 표로 펼쳤다.
- 주장 판정과 발산 종료 조건은 가능한 결과를 펼치는 큰 실험 아래에 배치했다.
- 최종 품질 우월성을 주장하지 않고, 비교 전에 보이는 재료와 확실성 상태가 달라졌다는 범위만 남겼다.

### AI self-check

- 첫 과교정 장면의 해석을 첫 절 안에서 닫고, 중반에 같은 사건을 다시 여는 반복을 제거했다.
- assignment 장면은 `더 근본적으로 / 더 추상적으로`의 오독 메커니즘을 맡겼다.
- forward bias는 진단, 다음 행동, 재발 감소가 다른 결과라는 stress test로 압축했다.
- 독립 판별 글의 계약을 반복하지 않고, 같은 판단 위치 밖이 필요해지는 조건까지만 연결했다.

## Texture review와 main 반영

shaping 반영 뒤 report-only texture review를 같은 세 묶음으로 다시 받았다. 이 단계에서는 논리를 새로 세우지 않고, 압축 과정에서 실제 판단 장면·사용자 개입·발견 문장·사실 범위가 평평해졌는지만 확인했다.

### 되살린 질감

- Current에서 Q4는 프로젝트 전체 역할, Q5는 최신 구현의 입력·결과·한계를 맡았다는 전후 차이를 복원했다. 마지막 운영 질문 목록은 하네스처럼 남기지 않고, 글쓴이가 이제 문장의 역할을 어떻게 보게 됐는지 산문으로 회수했다.
- 독립 판별에서 공개 정보와 test 입력이 충돌한 미성년자 티켓 절차를 짧게 복원했다. 별도 판정 역할과 판별 입력 경계는 다른 문제라는 발견도 명시했다.
- Scope control의 첫 장면은 실제 구현처럼 읽히던 완료형 시제를 제안형으로 고쳤다. 생생함은 남기되 구현 전 제안이라는 사실 상한을 우선했다.
- 판단 순서에는 이 글의 순서를 조사하며 같은 순서를 다시 어긴 재귀적 발견을 복원했다. 새 표는 `정적 목업`, `가정한 상태 변화`라고 라벨링해 실제 제품 검증처럼 읽히지 않게 했다.
- AI self-check에서는 과교정 복구 판단과 여러 기여 주체를 문단으로 나눴다. forward-bias 장면은 사용자가 같은 행동을 세 차례 멈췄다는 범위까지만 구체화했다.

### 되돌리지 않은 것

- Current의 Q1~Q5 전체 전후표는 복원하지 않았다. Q4/Q5 대비만으로 시간축 문제를 보여 주고, 설문 글로 중심이 이동하는 것을 막았다.
- 독립 판별의 두 번째 시스템 A/B 계보와 추가 수치는 복원하지 않았다. 닫힌 입력의 한계만 맡겼다.
- Scope control의 내부 감각인 `AI 회피성` 라벨은 다시 넣지 않았다. 공개 글에서는 관찰된 선택 압력과 결과가 더 정확하다.
- 판단 순서의 후보 수 계보와 질문 목록은 늘리지 않았다. 비교표가 가능한 결과와 통제력의 차이를 이미 보여 준다.
- AI self-check의 forward-bias 전체 대화 순서와 독립 판별 계약은 복원하지 않았다. 각각 stress test와 이웃 글 연결이라는 역할을 지켰다.
