# Near-final v3 build와 역추적

## v3를 만든 방식

v2는 독립 review가 시작된 시점의 hash로 동결했다. v3는 v2에 세 report를 기계적으로 합친 결과가 아니다.

1. evidence 교정은 직접 원천의 단위와 맞으면 우선 반영했다.
2. shaping 제안은 각 글의 중심과 다른 글의 소유권을 더 선명하게 할 때 반영했다.
3. texture 제안은 실제 장면, 사용자 개입, 고유한 리듬을 보호하는 범위에서 반영했다.
4. reviewer끼리 충돌하면 현재 active-state와 직접 원천, 글의 실제 효과를 main이 다시 대조했다.
5. v3 뒤에는 같은 reviewer가 regression pass를 수행했다. 새 기준을 추가하는 대신 v2의 장점이 사라졌는지와 교정이 새 왜곡을 만들었는지만 확인했다.

공통으로는 artifact 뒤의 중복 설명과 결말의 반복 판정문을 줄였다. 대신 다섯 글의 첫 장면, 사용자 판단 변화, 대표 artifact, 서로 다른 ending은 보호했다.

## 글별 역추적

### Current

거의 최종본에서 실제로 글을 지탱한 재료는 문서 분류표 자체가 아니었다.

- 현재 contract와 선택 이유가 같은 갱신 규칙을 가졌던 첫 장면
- 설문에서 최신 사건을 전체 시간축처럼 읽은 오독
- Git history에서 확인한 실제 활성 cursor와 갱신 흔적
- 병렬 작업과 저장소 밖 terminal event가 마지막 current에 들어오지 않은 한계

이 재료들이 합쳐져 `current`를 요약문이 아니라 전체 지도, 단일 cursor, 권위 원천을 다시 작동시키는 위치로 만들었다. 최근성 편향과 누락은 current가 실패했다는 새 중심으로 올리지 않고, 읽기 경로를 만든 뒤에도 쓰기 책임이 남는다는 운영 조건으로 두었다.

덜 중요해진 것은 파일 taxonomy를 완결된 규칙처럼 설명하는 일과 이 구조가 생산성을 높였다는 확대 주장이다. 현재 글 준비 과정의 재현은 판단 권한을 보여 주는 두 문장만 남겼다.

사용자가 읽은 뒤 결정할 항목은 `current.md`라는 공개 이름을 유지할지와 최종 제목이다.

### 독립 판별

글을 지탱한 재료는 reviewer를 한 명 더 둔다는 추상 원칙보다 서로 다른 검증 세계가 열린 실제 checkpoint였다.

- 문자열 `"false"`가 boolean 분기를 비껴간 최소 bug
- 같은 runner의 test method가 9개에서 15개로 늘어난 범위
- test 밖에서 수행한 source 대조와 설치형 자연어 E2E
- fixture와 공개 판매 조건의 모순을 별도 티켓으로 남기고 다시 판별한 과정
- 판별 출력과 main의 반영 판단을 분리한 recovery trace

닫힌 입력 밖을 보지 못한 다른 판별 사례는 독립 판별의 효용을 뒤집는 반례가 아니라, 역할 분리와 입력 경계가 별개라는 한계만 맡겼다. reviewer 수나 모델 차이는 중심에서 내려갔다.

사용자가 읽은 뒤 결정할 항목은 기술 case study로 먼저 공개할지와 다른 글과의 발행 순서다.

### Scope control

이 글을 살린 재료는 `vertical slice`라는 이름보다 두 구현안이 어디에서 끝나는지의 차이였다.

- 검색 결과 배열에서 끝나는 제안과 질문의 답·근거·상태까지 만드는 제안
- `15:00 → 16:00` source 변화와 `missing` 계약
- source 변화, evidence substring, 실제 route 소비를 확인한 test
- 실제 사용자 경로가 쓰지 않는 fact path를 제거한 결과

`작게`, `안전하게`, `빨리 보이게`라는 조건이 회피 의도를 증명한다고 쓰지 않았다. 관찰 가능한 범위는 그 조건 아래 화면에 바로 붙일 수 있고 성공 여부가 명확한 경로가 더 작은 완결처럼 제안됐다는 데까지다.

deterministic baseline은 제품 흐름의 대안이 아니라 재현 가능한 비교 기준으로 내렸다. 파일 수, 화면 수, UI 도달 여부는 마지막 기준에서 내려갔다.

사용자가 읽은 뒤 결정할 항목은 현재 제목의 강도를 유지할지와 product-architecture 글로 먼저 공개할지다.

### 판단 순서

글을 지탱한 재료는 `발산 후 수렴`이라는 표어보다 기준이 어느 단계에서 무엇을 끝낼 권한을 가졌는지의 변화였다.

- 현재 글감 조사에서 작업 cursor와 주장 상한이 후보 가치 판정으로 바뀐 재귀적 장면
- 첫 후보판을 덮어쓰지 않고 별도 pass로 보존한 선택
- `3 problems → 9 solutions → 3 outputs → 선택`으로 비교 재료가 달라진 과정
- 실제 제품이 아닌 세 방향의 정적 목업과 총 9개 snapshot
- 후보를 열어 둔 상태에서도 개별 주장은 `확인됨 / 불충분 / 모름 / 확인 필요`로 엄격하게 본 구분

화면 순회 이동과 후보 내부 상태 변화를 혼동하게 만드는 `8회 전환` 수치는 공개 원고에서 뺐다. 후보 수를 늘리는 것만으로 충분하지 않고 행동, 입력, 판단 권한, 결과의 차이가 나와야 한다는 관찰은 별도 사례로 키우지 않고 현재 artifact 해석 안에 남겼다.

`Output-informed problem selection` 재료는 이 글이 잠정 소유한다. 다만 유지 후보를 병합하거나 없앤다는 뜻은 아니다.

사용자가 읽은 뒤 결정할 항목은 이 재료 소유권을 확정할지와 learning-experiment 목소리를 유지할지다.

### AI self-check

글을 지탱한 재료는 AI가 틀렸다는 사실보다 정정 뒤에도 같은 판단축이 남을 수 있다는 세 장면이었다.

- `두 근거를 함께 보되 증명 범위는 분리 → 회사 방향 우선 과교정 → 관계 복구`의 교정된 시간순서
- “더 근본적으로”라는 요청을 “더 추상적으로” 읽은 assignment 장면
- 사용자가 같은 전진 방향을 멈춘 보존 발화 세 개와 이후 지침 변경

첫 사건은 회사와 사용자 중 어느 쪽이 더 중요한지 정하는 사례가 아니다. 서로 다른 근거가 무엇을 증명하는지의 관계가 교정 과정에서 사라진 사례다. self-check의 성과도 더 좋은 오류 설명이 아니라 문제 정의, 입력 범위, 바로 다음 행동이 달라졌는지까지 검사하게 된 변화로 제한했다.

독립 판별은 self-check가 계속 같은 frame을 재생산할 때 필요한 바깥 판단 위치로 짧게만 연결했다. 두 글을 합치지 않았다.

사용자가 읽은 뒤 결정할 항목은 했다체와 현재 제목을 유지할지, 독립 판별과 어느 순서로 공개할지다.

## 다섯 편을 함께 본 판정

v3에서 다섯 후보는 모두 독립 글로 살아남았다.

- Current는 긴 시간축에서 현재 권위와 갱신 경로를 다룬다.
- 독립 판별은 다른 검증 세계와 완료 선언 권한을 다룬다.
- Scope control은 작은 구현에서도 실제 소비자까지 남겨야 할 작용을 다룬다.
- 판단 순서는 생성, 주장 판정, 후보 종료의 권한 배치를 다룬다.
- AI self-check는 정정 뒤 판단축과 행동까지 검사하는 일을 다룬다.

겹치는 사건은 있지만 각 글에서 맡는 질문이 다르다. 이번 cycle에서 병합하거나 탈락시킬 근거는 확인하지 않았다. 첫 글, 발행 순서, 시리즈 여부, 최종 제목은 완성도가 낮아서 남은 작업이 아니라 사용자가 다섯 결과를 읽고 정할 편집 판단이다.
