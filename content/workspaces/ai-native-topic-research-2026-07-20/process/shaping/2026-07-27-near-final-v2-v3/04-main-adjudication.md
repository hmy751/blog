# v2 review main 판정

## 전체 판정

세 reviewer의 공통 결론을 채택한다.

- 다섯 중심을 다시 열지 않는다.
- 새 기준을 추가하지 않는다.
- v2의 대표 사건과 artifact를 줄이지 않는다.
- v3는 후기의 두 번째 증명 사례, artifact 뒤 재설명, 중복 판정문을 국소 수정한다.
- evidence가 요구한 fixture, test 범위, marker, 전환 수 교정은 전부 반영한다.

이번 v2가 post-sync v1보다 실제로 풍부해졌다는 texture 판정을 중요하게 본다. v3의 압축이 다시 v1 같은 운영 요약으로 돌아가지 않게 글마다 고유한 장면과 결말을 먼저 보호한다.

## Current

### 채택

- committed version의 actual active cursor 의미를 풀어 evidence 교정을 반영한다.
- 분리 전후 표, current 예시, 질문별 시간축 trace를 핵심 artifact로 유지한다.
- 역할 표 뒤의 긴 재설명을 줄인다.
- `current = router`는 실제 current 예시 뒤에서 한 번만 무겁게 착지시킨다.
- terminal gap과 update ownership을 후반의 주된 tradeoff로 유지한다.
- 마지막은 `active control` 문장으로 닫고 직전 중복 판정문을 덜어낸다.

### 조정 채택

- Git 수치는 삭제하지 않는다. 실제로 덮어쓴 상태였다는 드문 운용 근거이므로 한 문단으로 보존하되 품질 지표가 아님을 바로 붙인다.
- 현재 blog 자기참조 장면도 삭제하지 않는다. active-state의 권위를 실제로 다시 적용한 재현이지만, 별도 대단원 대신 update ownership 아래 한 문단으로 축소한다.
- `current.md`는 이 글의 공개 개념명으로 v3에서도 잠정 유지한다. 현재 blog 내부 구역명 `active-state`, `process`는 `현재 상태 영역`, `과정 기록`으로 일반화한다. 최종 제목 선택은 사용자가 v3를 읽은 뒤 결정할 수 있다.

## 독립 판별

### 채택

- seller 답변은 전부 `검증용 fixture 답변`으로 명시한다.
- reviewer self-certification은 실측 사실이 아니라 설계 위험으로 낮춘다.
- 공개용 code 소개의 제작 meta를 제거한다.
- 판별 회수 trace를 네 덩어리로 압축한다.
- 결말의 checklist를 세 축으로 줄인다.

### 조정 채택

- 다른 답변 시스템 반례는 삭제하지 않는다. 판별 역할 분리와 입력 경계가 다른 문제라는 핵심 한계를 맡는다. 다만 세부 failure type을 한 문단으로 압축해 Scope 글과의 중복을 줄인다.
- clean-room이 아니라는 상한은 방어처럼 보여도 필수 근거 범위이므로 유지한다.

## Scope control

### 채택

- 조건이 쉬운 경로를 유발했다는 인과를 evidence 권장 문장으로 낮춘다.
- source 변경 test는 두 fixture 범위로 쓴다.
- 상태에 따른 다음 행동은 test 결과가 아니라 제품 계약임을 분리한다.
- 표를 공개용으로 만들었다는 제작 meta를 `제품 계약의 최소 형태`로 바꾼다.
- 표와 test 예시 뒤의 재설명을 줄인다.
- 마지막 세 원칙문을 실제 소비자와 마지막 판단 기준 두 호흡으로 줄인다.

### 조정 채택

- deterministic baseline은 삭제하지 않는다. UI까지 연결하면 된다는 오독과 deterministic 구현 일반화를 동시에 막는 반례다. 별도 `##`에서 `줄일 것은 폭` 절 아래 `###`로 내리고 압축한다.
- title은 관찰된 설계 갈림길을 가리키며 첫 장면에서 제안임을 즉시 밝히므로 v3에서도 유지한다.

## 판단 순서

### 채택

- 과거 제품 조사 내부 세 절을 `###`로 내려 실험의 층위를 보이게 한다.
- blind 상한과 output artifact의 방어 문단을 압축한다.
- 수렴 절은 `수렴을 없앤 것이 아니라 입력을 바꿨다`와 `비교 가능한 차이`만 남기고 현재 bookend에 결말을 넘긴다.
- 결말의 세 판정문을 두 호흡으로 줄인다.

### 조정 채택

- `8회 전환`은 public v3에서 제거한다. 직접 원천 대조로 9개 화면을 순회한 8번의 이동과 후보 내부 6번의 상태 변화가 다른 단위임이 확인됐고, 이 숫자는 글의 판단을 바꾸지 않는다.
- 총 9개 snapshot과 실제 제품이 아닌 정적 목업이라는 사실만 본문에 남긴다. 8/6 단위 교정은 evidence review와 이 판정에 보존한다.
- v1에서 사라진 rubric-first 반복 관찰을 두 문장으로 복구한다. 숫자나 새 중심을 추가하지 않고, 후보 수를 늘리는 것과 행동·입력·결과 차이를 펼치는 것이 다르다는 질감을 맡긴다.

## AI self-check

### 채택

- 첫 점검, 두 번째 점검, 작업 조율 AI의 역할을 첫 사건에서 한 문장으로 식별한다.
- `더 근본적 / 더 추상적` 대표 문장은 보호하고 주변 판정문을 한 번 덜 착지시킨다.
- forward-bias는 보존된 사용자 발화 세 개라는 evidence 단위로 고친다.
- 진단·직후 행동·장기 재발을 각각 한 문장으로 압축한다.
- self-check를 발동하지 않는 경우와 발동하는 경우를 각각 한 문장으로 줄인다.
- 했다체와 마지막 두 문장은 유지한다.

### 기각

- 첫 사건의 증명 역할 설명을 더 짧게 줄이라는 방향은 기각한다. 이 글의 핵심은 회사와 사용자 중 어느 쪽이 큰지가 아니라 서로 다른 근거의 증명 범위이므로, 초반 관계를 충분히 이해할 재료가 필요하다.
- 세 상태 도식을 표로 바꾸거나 추가 artifact를 넣지 않는다. 현재 도식이 회고 호흡을 가장 잘 보존한다.

## v3 반영 뒤 확인할 것

- 압축 때문에 실제 장면과 사용자 개입이 다시 설명문으로 줄어들지 않았는가.
- evidence 교정이 새 방어 문단을 만들지 않고 주장 가까이 붙었는가.
- 다섯 ending이 서로 다른 글의 발견으로 남는가.
- Current와 판단 순서, 독립 판별과 Scope의 겹치는 사건이 각 글의 소유권 안에서 충분히 구분되는가.
