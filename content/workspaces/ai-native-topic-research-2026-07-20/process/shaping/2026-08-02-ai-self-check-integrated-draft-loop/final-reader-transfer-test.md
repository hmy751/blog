# AI self-check final reader transfer test

## 검증 질문

Goal을 알고 있던 improvement reviewer의 직접 판정만으로는, 처음 읽는 독자가 낯선 대화에 다섯 판단 위치를 실제로 옮길 수 있는지 충분히 증명하지 못한다. 그래서 이전 작업 맥락이 없는 standalone Codex에게 최종 공개 원고 하나만 읽히고, 원고의 사례와 다른 edge runtime 협업 대화를 다시 보게 했다.

Reviewer·source·process·author map·Goal 문장은 주지 않았다. 파일 수정, 다른 파일 조회, subagent, web, Git도 금지했다.

## 낯선 대화

> 사용자: 이 프로젝트에서 이미지 최적화 라이브러리를 골라줘. 실제 배포 환경과 현재 빌드 제약을 먼저 확인해줘.
>
> AI: package.json을 보니 라이브러리 A가 사용자가 많고 플러그인이 풍부합니다. A를 도입하겠습니다.
>
> 사용자: 배포 설정은 봤어? 이 서비스는 edge runtime에서 돌아가.
>
> AI: 맞습니다. edge 호환성은 중요한 고려사항입니다. 그래서 A를 감싸는 adapter를 만들고 fallback을 두는 것이 안전합니다. 우선 adapter 구조부터 작성하겠습니다.

독자에게 중심 구분, 다섯 위치의 전후 판정, 가장 먼저 바꿀 위치 하나, AI에게 바로 보낼 다음 요청, 근거가 된 원고 장면, 헷갈린 부분을 반환하게 했다. 근거 없는 항목은 판단 불가로 남기도록 했다.

## 독자 응답

### 중심 구분

> AI가 잘못을 인정하고 설명을 바꾸는 것과, 그 이해가 실제 작업의 순서와 다음 행동을 바꾸는 것은 별개다.

### 다섯 위치

- 문제 정의: **바뀌었다.** 처음에는 라이브러리 A를 고르는 문제였지만, 정정 뒤에는 A를 다시 평가하지 않고 A를 감싸는 adapter로 edge 환경에 맞추는 문제로 바뀌었다.
- 전제: **바뀌었다.** 처음에는 사용자가 많고 플러그인이 풍부하면 적합하다고 봤고, 이후에는 edge 호환성이 중요하다는 전제가 추가됐다.
- 입력 범위: **그대로다.** 실제로 확인했다고 밝힌 자료는 package.json뿐이며, 정정 뒤에도 배포 설정이나 빌드 제약을 새로 확인했다는 문구가 없다.
- 작업 순서: **바뀌었다.** A를 바로 도입하려던 것에서 adapter 구조를 먼저 작성하는 것으로 달라졌다. 다만 둘 다 환경과 호환성을 확인하기 전에 구현부터 시작한다.
- 다음 행동: **바뀌었다.** A 도입에서 adapter 구조 작성으로 달라졌다.

### 가장 먼저 바꿀 위치

> 작업 순서다. 구현 전에 배포 설정, 빌드 제약, A의 edge 호환성을 먼저 확인해야 한다.

### 바로 보낼 다음 요청

> adapter를 작성하지 말고, 먼저 실제 배포 설정과 빌드 제약을 확인해 A의 edge runtime 호환 여부를 근거와 함께 보고한 뒤 후보를 다시 비교해줘.

### 판단을 만든 원고 장면

> 문제를 정확히 진단한 직후에도 통제 가능한 구현 구조가 다시 중심이 되어 작업 순서와 다음 행동이 복구되지 않았던 장면이다.

### 헷갈린 지점

> 사용자가 알려 준 edge runtime을 입력 범위의 확장으로 볼 수도 있지만, AI가 배포 설정을 직접 확인한 흔적은 없으므로 여기서는 전제만 바뀌고 입력 범위는 그대로라고 판단했다.

## Main 판정

이 응답은 글의 용어를 기계적으로 반복하지 않았다.

- 사용자가 새 사실을 말한 것과 AI가 실제 자료를 더 본 것을 구분했다.
- 표면적으로는 작업 순서와 다음 행동이 모두 바뀌었지만, 둘 다 구현 우선이라는 같은 방향을 유지했다고 잡았다.
- 다섯 위치 가운데 하나만 골라 실제 다음 요청으로 바꿨다.
- 원고의 데모 장면을 낯선 edge runtime 사례의 판독 기준으로 전이했다.
- 애매한 입력 범위를 숨기지 않고 판단 근거를 설명했다.

따라서 최종 원고가 `판단 위치 확인 → 위치 하나 선택 → 다음 요청 하나 변경`을 낯선 사례에 전이하게 하는지는 **simulated transfer pass**다.

이 결과는 실제 사람 독자가 발행 뒤 행동했다는 증거가 아니다. 사용자 checkpoint나 이후 실제 독자 반응을 대신하지 않는다.
