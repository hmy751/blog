# AI self-check 저자·원고 지도

이 지도는 확정 목차나 문장 지시서가 아니다. 현재 원고, 사용자 인터뷰, 생성 계보 packet, 필요한 직접 원천을 대조해 한 편의 완결된 수정본이 해결해야 할 판단을 모은다. 작성 worker는 이 지도를 사용하지만 fresh reviewer는 보지 않는다.

## 고정 Goal과 대상

> AI가 결론을 고쳤거나 잘못을 인정했다는 데서 멈추지 않고, 독자가 자신의 AI 협업에서 문제 정의·전제·입력 범위·작업 순서·다음 행동 중 무엇이 실제로 달라졌는지 판별할 수 있게 하는 글. 읽은 뒤에는 최근 대화 하나를 다시 열어, 답이 아니라 답을 만든 판단 위치를 확인하고 다음 동작 하나를 바꿔 본다.

- 대상: AI와 일하며 판단과 통제 방식을 고민하는 개발자
- 주된 글 유형: Retrospective / Meta
- 함께 켤 관점: 개발자가 무엇을 문제로 보고 어떤 판단과 작업 방식을 바꿨는지가 보여야 한다.

## 이번 원고가 붙들 중심

이 글은 `AI의 메타 분석은 쓸모없다`는 글이 아니다. AI가 어긋남을 정확한 언어로 붙잡아 주는 순간에는 실제 가치가 있었다. 그러나 좋은 진단, 그 진단을 현재 작업에 옮긴 직후 행동, 비슷한 상황에서의 재발 감소는 서로 다른 결과였다.

글이 끝까지 따라갈 질문은 다음과 같다.

> AI가 원인을 잘 설명하거나 별도 판별자가 더 정확한 판단을 돌려줬을 때, 문제 정의·전제·입력 범위·작업 순서·다음 행동 가운데 실제로 무엇이 달라졌는가.

self-check의 역할은 AI에게 반성을 시키거나 자동 정답을 받는 데 있지 않다. 사용자와 AI가 만든 결과에서 어긋남이 생긴 위치를 다시 구성하고, 원래 작업의 해결로 돌아갈 수 있게 만드는 데 가깝다.

## 현재 원고의 문단 역할 지도

### 도입 — 2026-05-21 생성 발단

- 현재 역할: 보이는 폴더만 탐색 범위로 삼은 표면 오류와, `더 근본적으로`를 자기 판단 점검이 아닌 더 큰 일반론으로 번역한 두 번째 어긋남을 보여 준다.
- 작동하는 점: `AI는 문제를 설명하고 있었지만, 정작 자신은 문제 밖의 해설자로 남아 있었다`가 skill 생성 이유와 중심 질문을 함께 연다.
- 보호 판단: 현재까지는 이 사건이 생성 배경과 첫 장면으로 가장 강하다. 더 좋은 직접 원천이 나오지 않는 한 교체하지 않는다.

### 최초 inline 규칙 — 답을 만든 위치를 다시 보기

- 현재 역할: self-check가 처음에는 같은 AI가 자기 탐색·분류·전제·정정 반응을 원인에 넣고 원래 작업으로 돌아가는 규칙이었다는 사실을 설명한다.
- 작동하는 점: 최초 계약과 후대 fresh 계약을 소급해 합치지 않는다.
- 개선 필요: 규칙 설명이 운영 문서처럼 길어지지 않게 하면서도, `결과에서 입력을 역추적하지 않은 탐색 종료 조건`이라는 실제 변화는 남긴다.

### 2026-06-05 적용 장면 — 좋은 진단과 중심 유지 실패

- 현재 역할: 정확한 원인 설명과 직후 행동 변화가 갈릴 수 있음을 보여 준다.
- 작동하는 점: `불확실성을 통제 가능한 데모로 바꾸려는 충동`이라는 언어와, 설명 뒤에도 baseline·extractor·상태 판정이 다시 중심이 된 대비가 선명하다.
- 빠진 저자 판단: 사용자는 이 분석을 실제로 `좋은 분석`, `핵심`이라고 봤다. 정확한 언어와 `AI가 알아들었다`는 느낌 자체도 가치였다. 이를 단지 다음 실패의 전주로 낮추지 않는다.

### 2026-06-12·17 — fresh 판별과 Main 회수의 분리

- 현재 역할: 같은 맥락 안에서 스스로 점검하는 한계 때문에 별도 판단 위치가 필요해졌고, 좋은 판별과 좋은 적용은 다른 결과였음을 보여 준다.
- 작동하는 점: fresh가 `다른 답`을 낸 것이 아니라 Main이 놓친 판단축을 다른 문제 정의로 다시 열었다는 점이 살아 있다.
- 개선 필요: 역할 계약 연표뿐 아니라 사용자가 그 근본 관점을 왜 좋게 봤는지, Main이 길고 어려운 설명으로 회수했을 때 어디서 다시 막혔는지 저자 판단을 더 보이게 한다.

### 2026-07-10 AX 조사 — 맞는 판정의 오적용과 실제 복구

- 현재 역할: 별도 판별이 맞아도 Main이 적용하면서 기존 판단 경로를 지울 수 있음을 보여 준다.
- 작동하는 점: 회사 방향과 사용자 문제라는 두 주장·두 증명 범위를 다시 분리했고, 둘의 접점에서 다음 조사 질문을 고르는 실제 행동까지 바뀌었다.
- 개선 필요: 이 사건을 `반대 방향으로 한 번 크게 고침`만으로 일반화하지 않는다. 사용자가 말한 과교정의 더 넓은 감각은 정정 때마다 앞선 이해를 누적하지 못하고 다른 쪽으로 움직이며 중심을 잃는 핑퐁이다.

### 2026-07-14·20 — 입력 계약과 호출 문턱 조정

- 현재 역할: fresh를 더 붙이는 성공담이 아니라, Main의 입력 포장으로 생긴 오염과 과발동 비용을 다시 줄인 과정을 보여 준다.
- 작동하는 점: `inline → fresh → 원문 범위 pull → 반복 실패에만 호출`이라는 변화와 첫 정정은 평범한 대화로 처리하는 경계가 있다.
- 개선 필요: 운영 계약 명사만 이어지지 않게 `왜 좋았고 무엇이 오염됐다고 느꼈는가`라는 저자 판단을 사건과 붙인다.

### 결말 — 독자의 대화로 옮기기

- 현재 역할: 결론보다 판단 위치와 직후 행동을 보게 하고, 별도 판별이 필요한 문턱을 준다.
- 작동하는 점: 문제 정의·전제·입력 범위·작업 순서와 다음 검색·비교·수정을 분리한다.
- 개선 필요: 체크리스트보다 먼저 사용자가 원했던 회복을 되찾는다. 대화와 질문 상황을 정확히 다시 구성하고, 맞는 해결책과 원래 작업으로 돌아가는 것이 목적이다.

## 사용자가 직접 확인한 경험과 현재의 깨달음

### 당시 경험과 source가 함께 지지하는 판단

- 문제는 표면 원인을 고치는 데서 끝나지 않았다. 근본 문제를 지적받은 뒤에도 AI가 자기 탐색과 판단을 원인에서 빼고 엉뚱한 일반론이나 다른 해결 방향으로 이동했다.
- 사용자가 원한 것은 더 큰 사과나 더 추상적인 설명이 아니었다. 대화 흐름을 다시 보고 어긋난 위치와 문제 제기의 뉘앙스를 잡아, 그 이해에 맞는 해결책으로 작업을 이어 가는 것이었다.
- 메타 분석 자체는 실패가 아니었다. 본질을 정확한 언어로 잡아 `AI가 알아들었다`는 느낌을 준 순간에는 분명한 가치가 있었다.
- 문제는 그 포인트가 다음 답과 작업에서 안정적으로 유지되지 않는 경우였다.
- fresh한 판단 위치는 Main의 기존 맥락에 덜 묶인 문제 정의를 돌려줄 수 있었다. 그러나 그 판정을 Main이 어떻게 회수하는지는 별도 결과였다.

### 계속 사용하며 뒤늦게 선명해진 현재 회고

- 사용자는 self-check를 언제나 완성된 정답을 들고 호출한 것이 아니었다.
- 먼저 `뭔가 어긋났다`는 작업 감각이 있었고, AI가 내놓은 틀릴 수 있는 후보 진단을 맞다·아니다로 다시 구분하면서 중요하게 보던 기준을 더 정확히 말한 때가 있었다.
- 상황에 따라 사용자가 Main과 질문을 주고받으며 직접 sync할 수도 있고, 같은 판단축이 반복되거나 기존 맥락과 분리된 관점이 필요할 때 fresh 판별을 열 수도 있다.
- 이 깨달음은 2026-05-21 최초 설계 의도가 아니다. AI를 계속 다루며 당시 경험의 의미가 나중에 선명해진 현재의 이해다.
- 제3 판단은 사용자의 정답을 대신하는 것이 아니라, 어긋남의 감각을 검토 가능한 문제 정의와 선택지로 바꾸는 재료가 될 수 있다.

공개 글에서 사용할 수 있는 상한은 다음과 같다.

> 나는 어긋남을 먼저 느꼈지만 처음부터 원칙을 완성된 문장으로 갖고 있지는 않았다. AI가 내놓은 진단을 맞다·아니다로 다시 구분하는 과정이, 내가 중요하게 보던 기준을 더 정확히 말하게 해 준 때가 있었다.

## 현재 원고에 빠졌거나 평평해진 저자 판단

### Material

1. 정확한 메타 분석 자체의 가치가 약하다. `좋은 분석 / 중심 유지 실패`의 양면을 함께 살려야 한다.
2. 사용자가 완성된 정답을 가진 심판처럼 보인다. 어긋남의 감각과 후보 진단을 대조하며 기준이 선명해진 현재 회고가 필요하다.
3. fresh 구간에는 저자가 무엇을 좋게 봤고 어디서 다시 막혔는지가 운영 계약보다 약하다.
4. 과교정이 AX의 한 번의 오적용에 좁혀져 있다. 정정 때마다 중심을 누적하지 못한 핑퐁 감각은 source가 허용하는 범위에서 보강해야 한다.
5. 사용자가 원한 최종 회복은 체크 항목 준수보다 문제 상황을 다시 구성하고 원래 해결로 돌아가는 것이었다.

### Shaping

1. `진단 문장은 맞았지만`이라는 대비가 좋은 진단의 가치를 실패의 전주로만 읽히게 할 수 있다.
2. fresh 판별, Main 회수, 사용자 판단의 역할 도식이 사용자를 최종 정답 보유자로 고정한다.
3. 중후반이 `별도 판별 → AX 사례 → 입력·호출 계약`이라는 운영 연표로 느껴질 수 있다. 각 구간이 저자의 판단을 어떻게 바꿨는지 더 선명해야 한다.
4. 결말의 세 기준은 유효하지만, `상황을 다시 구성하고 작업으로 돌아간다`는 글 전체의 목적을 먼저 회수한 뒤 독자 행동으로 내려가야 한다.
5. 7월 9일 장면을 넣는다면 새 대형 사례가 아니라 `규칙을 고치던 논의에서도 같은 모드가 돌아왔다`는 짧은 반례 역할만 맡긴다.

### Texture와 Reader Flow

1. `판단 위치`, `회수`, `입력 범위`, `호출 문턱`, `계약` 같은 운영 명사가 연속되는 구간은 내부 문서처럼 들릴 수 있다.
2. 여러 절이 `사례 → 추상화 → 새 기준`으로 같은 cadence를 반복한다. 최소 2~3개 절의 문단 역할을 달리할 수 있다.
3. 도식과 리스트는 이미 충분하다. 새 장치를 자동으로 더하지 않는다.
4. 개인적 판단 문장은 사건과 연결해 보호한다. 회고를 일반 규칙 문장으로 평평하게 만들지 않는다.
5. 소제목은 같은 무게의 결론문만 이어지지 않게 문제 장면, 판단 전환, 현재 회고의 층위를 드러낼 수 있다.

## 보호할 흐름과 표현

### 흐름

- 문제 인식 → 최초 self-check 생성 → 실제 사용에서 기대가 깨짐 → fresh 판단 위치 도입 → 회수의 한계 → 입력과 호출 방식 조정 → 독자의 다음 행동
- 진단 정확도 / 직후 행동 변화 / 장기 재발 감소의 분리
- fresh 판별 / Main 회수 / 사용자 판단이 서로 대신하지 않는 구조
- 현재 회고와 당시 사실의 시간 분리

### 살아 있는 표현과 장면

- `AI는 문제를 설명하고 있었지만, 정작 자신은 문제 밖의 해설자로 남아 있었다.`
- `불확실성을 통제 가능한 데모로 바꾸려는 충동`
- 정확한 진단과 그 직후 다시 통제 가능한 구현 계획으로 돌아간 대비
- 회사 방향과 사용자 문제의 두 증명 경로
- `같은 표현 횟수`가 아니라 같은 문제 정의·입력 범위·작업 모드가 돌아오는지를 본다는 구분
- 마지막에 최근 AI 대화 하나를 다시 열게 하는 구체 행동

이 문장들을 모두 원문 그대로 보존하라는 뜻은 아니다. 이들이 맡은 발견과 감각을 평평하게 만들지 않는다.

## 다시 열어 둔 구조

- 최초 사건을 더 좋은 직접 원천이 있을 때만 교체할 수 있다. 현재 지도에서는 5월 21일을 유지한다.
- 중후반 절 순서, 문단 역할, 소제목, 제목은 개선할 수 있다.
- 7월 9일 핑퐁 장면을 짧게 넣거나 기존 장면의 해석으로 흡수하는 두 선택을 열어 둔다.
- 현재 회고는 중후반 역할 분담과 결말 사이에 둘 수 있지만, 별도 대형 성공 사례처럼 키우지 않는다.
- 대표 사건, 큰 구조, 글의 중심, 사용자 경험의 의미를 바꾸려면 작성 worker가 확정하지 않고 Main에게 이유와 대안을 보고한다.

## 작성 worker가 한 편의 원고에서 해결할 우선 과제

1. 도입의 생성 인과와 현재 중심 질문은 유지하되, 글 전체가 `분석은 실패했다`는 단선으로 읽히지 않게 한다.
2. 6월 5일 장면에서 정확한 언어를 얻은 저자의 실제 가치와, 그 뒤에도 중심이 유지되지 않은 한계를 같은 무게로 살린다.
3. fresh 판별·Main·사용자 역할을 `정답 전달`이 아니라 `후보 판정 → 현재 작업으로 번역 → 실제 문제와 대조하며 남은 기준을 좁힘`으로 더 정확히 쓴다.
4. 과교정을 핑퐁과 중심 누적 실패까지 넓히되, source 밖 대표 장면이나 내면을 만들지 않는다.
5. 지금의 깨달음을 분명한 시간 표지와 함께 넣고, 결말을 `문제 상황 재구성 → 다음 판단 위치 확인 → 다음 동작 하나 변경`으로 회수한다.
6. 전체 원고의 소제목·문단 역할·리듬을 다시 보되, 장면과 1인칭 판단을 운영 문서나 체크리스트로 평평하게 만들지 않는다.
