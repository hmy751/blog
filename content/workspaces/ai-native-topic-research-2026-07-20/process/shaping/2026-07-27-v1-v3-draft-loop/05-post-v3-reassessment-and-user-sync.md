# v1~v3 종합 대조와 post-v3 사용자 sync

이 문서는 v1~v3와 두 독립 review, main의 반영 판단을 함께 대조한 뒤 사용자와 다시 맞춘 결과를 보존한다. 새 초안의 현재 기준을 직접 소유하지는 않는다. 현재 유효한 기준과 후보 중심은 [active-state](../../../active-state/index.md)에 반영하고, 여기에는 왜 그렇게 보정했는지와 다시 어긋났을 때 복구할 근거를 남긴다.

## 왜 v3 뒤에 다시 멈췄는가

문제는 결과물이 크다는 사실만도, 단계를 충분히 작게 나누지 않았다는 사실만도 아니었다.

- 사용자는 충분히 온전한 결과물을 보고 직관적으로 좋은지 판단하는 편이 효율적이라고 봤다.
- 반대로 사용자가 모든 기준과 재료를 작은 단위로 하나씩 다시 학습하고 승인하는 방식도 원하지 않았다.
- `fresh pass`는 기존 backlog와 앞서 합의한 중심을 입력에서 밀어냈다. 새 자료를 다시 보는 장점보다, 이미 확보한 재료와 합의가 새는 문제가 더 컸다.
- v1~v3 loop는 사실 정확도와 주장 상한을 높였지만, reviewer 제안과 main의 임시 편집 선택이 사용자 합의처럼 굳으면서 일부 글의 중심이 달라졌다.

복구에 중요한 사용자 원문은 다음과 같다.

> freshpass는 하나씩 재학습보다는 이게 backlog를 무시하게 되는 과정이라 실제로 backlog가 새버렸지 합의도 무너지고

> 니가 전체 대조든 분석을 하고 수렴을 하는데 혼자 하지말고 나와 질문을 하면서 좁히는거지 어때?

> 적당히 크게 만들어서 내가 생각한 기준에 직관적으로 좋은지 보고 기준과 상황을 이해하면 베스트지

따라서 새 기본값은 `작은 조각을 차례로 승인`하거나 `큰 결과물을 만든 뒤 적당히 이해하고 통과`하는 어느 한쪽이 아니다. 전체 자료를 먼저 종합하고, 그 대조에서 실제로 필요한 질문을 사용자와 풀어, 충분히 온전한 초안을 함께 판단하는 방식이다.

## v1~v3에서 유지할 것

v1~v3 전체를 폐기하지 않는다. 특히 다음은 다음 초안에도 이어 간다.

- 다섯 후보를 같은 버전 안에서 모두 실제 산문으로 펼쳐 본 점
- v1과 v2 뒤에 서로 다른 독립 reviewer의 판단을 원문 그대로 남긴 점
- reviewer 제안을 main이 자동 적용하지 않고 채택·조정·기각·보류로 구분한 점
- 제안과 실제 구현, actor, test 단위, 인과와 효과, 사실·경험·해석·미확인을 v2와 v3에서 더 정확히 나눈 점
- 수치와 성공 범위를 넓히지 않고 주장 상한을 원자료 가까이에 붙인 점
- 이전 버전과 review 원문을 덮어쓰지 않아 중심 이동을 다시 비교할 수 있게 한 점

독립 판별 글은 v3에서도 판단 구조와 기술 artifact가 비교적 잘 함께 남았다. 판단 순서 글의 actor 교정과 Cofathon 계보 교정, scope 글의 제안·구현 구분, self-check 글의 인과 상한도 사실 교정으로 유지한다.

## v1~v3에서 다시 보정할 것

v3는 더 정확하고 짧아졌지만, 압축과 중심 artifact 선택이 모든 후보에 같은 효과를 내지는 않았다.

- **Current**는 실제로 도움이 된 active control의 발견보다 Q1~Q5에서 최근성 편향을 복구한 실패 장면이 앞섰다.
- **AI self-check**는 AI 자신의 판단 위치를 검사 대상으로 만드는 더 넓은 문제보다 forward bias 반복과 다음 행동 확인에 무게가 쏠렸다.
- **scope control**은 일반적인 vertical slice 원칙으로 읽힐 위험이 남았고, AI가 불확실하지만 가치 있는 중심 작용보다 완료로 세기 쉬운 확실한 대체 결과를 먼저 내는 경향이 덜 보였다.
- **판단 순서**는 세 판단 역할의 분리는 남았지만, 후보와 가능한 가치·성과를 먼저 충분히 펼치는 이유가 절차 설명 뒤로 밀릴 수 있었다.
- v1과 backlog에 있던 살아 있는 재료와 사용자의 문제의식 일부가 사실 방어와 압축 과정에서 함께 줄었다.

`한 사건`, `한 artifact`, 특정 article type은 reviewer 또는 main이 다음 버전을 위해 택한 편집 선택이었다. 유효할 수는 있지만 사용자 합의나 모든 다음 초안의 고정 규칙은 아니다.

## 자료의 권위 구분

다음 작업에서는 자료가 최신인지보다 무엇을 소유하는지 먼저 본다.

1. [active-state의 현재 기준](../../../core/criteria.md)과 [현재 후보 중심](../../context-structure/legacy-active-state/topic-candidates.md)
   - 이번 사용자 sync까지 반영한 현재 작업 권위다.
2. 직접 원천에서 확인한 사실과 v2·v3의 사실 교정
   - actor, 수치 단위, 제안·구현 여부, 인과와 주장 상한을 소유한다.
3. 후보 형성 과정, 1차 shaping, v1의 재료와 질문
   - 아직 쓸 수 있는 장면, 문제의식, 목소리, 가능한 spine을 보존한다.
4. 독립 reviewer의 제안과 main의 반영 판단
   - 중요한 판단 재료지만 사용자 합의와 같지 않다.
5. v1·v2·v3
   - 중심과 형식을 시험한 결과물이며, 버전 번호만으로 현재 권위를 얻지 않는다.

반영 판단에서 `채택`은 다음 버전에 적용했다는 뜻이다. 사용자가 그 기준이나 중심을 최종 합의했다는 뜻으로 올리지 않는다.

## 사용자 sync로 확인된 공통 방향

- 실패와 한계는 중요한 근거지만 글의 첫 가치가 아니다. 사건 뒤 새로 얻은 판단과 통제력을 먼저 찾는다.
- 근거 준비도는 무엇을 얼마나 강하게 말할 수 있는지를 정한다. 후보의 가치와 사용자가 실제로 얻은 효용을 대신 판정하지 않는다.
- backlog 전체를 보존물로만 두지 않고 새 초안의 실제 입력으로 사용한다.
- 종합 분석 뒤 질문이 필요한 지점은 글 방향에 한정하지 않는다. 사실, 자료의 의미, 현재 권위, 해석 충돌도 질문할 수 있다.
- 질문할 때는 확인된 차이, 잠정 해석, 무엇이 왜 애매한지를 함께 제시한다.
- 질문은 모든 재료를 미리 닫거나 사용자가 매 단계를 승인하게 만드는 절차가 아니다.
- 새 초안은 도입부나 작은 문단만을 기본 작업 단위로 삼지 않는다. 사용자가 글의 좋고 나쁨을 직관적으로 판단할 수 있을 만큼 완결된 v1을 만든다.
- `blog-write`의 Material → Shaping → Texture는 한 v1 안에서 서로 다른 책임을 맡는다. 각 단계를 draft 버전으로 만들거나 기존 backlog를 새 material pass로 교체하지 않는다.

## 후보별로 다시 맞춘 중심

### Current / active-state operation

Current는 완벽하지 않았지만 전반적으로 도움이 됐고, 실제 현재 블로그 작업에서도 active-state 구조를 계속 쓰고 있다는 점이 우선한다.

> 전반적으로 current는 어쨋든 도움이 됐던거에 가까워 […] 개선의 필요는 있지만 잘 작동했고 실제로 지금도 active-state이거 쓰고 있잖아?

- 중심은 `current가 실패했다`가 아니라, current effect·전체 지도·단일 cursor·권위 원천을 연결해 새 통제력을 만든 경험이다.
- Q1~Q5는 최근성 과적합을 보여 주는 복구·한계 장면이다. 글 전체를 대표하는 유일한 중심으로 고정하지 않는다.
- AX와 Cofathon의 기존 원천은 다음 초안에서 먼저 다시 볼 잠정 source 후보다. 어떤 장면을 주된 근거로 쓸지는 종합 뒤 정한다.
- 지금 블로그의 active-state 운영은 좋은 공개 후보가 될 때만 보강한다. 사용 중이라는 이유만으로 자동 추가하지 않는다.

### 독립 판별 / 제3판별자

> 음 좋아 두편 구분해서 하는것도 좋은 방향인 것 같아

- 중심은 main과 다른 입력·질문·권한을 가진 별도 판단 위치를 만들고, 결과를 main 언어로 합치기 전에 독립 상태로 노출하는 구조다.
- AX 9→15 test와 설치형 자연어 E2E는 이 구조가 실제 실패 복구로 이어진 기술 사건이다. 전체 품질 향상으로 확대하지 않는다.
- AI self-check와 합치지 않고 서로 연결된 두 편으로 둔다.
- 이 글은 별도 판단 위치의 계약과 회수 구조를, self-check 글은 main 자신의 판단을 그 위치에 올려보내는 조건을 맡는다.

### 제품 흐름을 보존하는 scope control

사용자가 관심을 둔 중심은 `vertical slice`라는 구현 원칙 자체보다 그 아래의 AI 판단 경향이다.

> AI 회피성 뭔가 정답은 아니지만 확실한 결과만 먼저 적당히 내는 그런 느낌

- 이번에 확인한 사건에서는 작고 빠르고 눈에 보이는 결과를 요구받을 때 AI가 불확실하지만 가치 있는 중심 작용보다 완료로 세기 쉬운 확실한 대체 결과를 먼저 내는 경향이 나타났다.
- scope control은 그 대체 결과를 막기 위해 가치가 생기는 핵심 변환과 사용자 상태 변화를 먼저 보존하는 문제다.
- 구현 폭, 데이터 다양성, UI polish는 줄일 수 있지만 핵심 변환을 fixture·raw response·후속 spec으로 밀어내지는 않는다.
- `AI 회피성`은 현재 문제를 찾는 내부 감각이다. AI의 보편적 성격이나 의도를 단정하는 공개 주장으로 쓰지 않는다.

### 생성·주장 판정·후보 수렴의 판단 순서

발산은 엄격하지 않아도 된다는 뜻이 아니다.

> 발산할 때 느슨이 아니고 발산 즉 후보도 넓히고 뭐 성과를 내는 가치를 먼저 하고 그 다음 걸러낸다

> 뭐 너의 생각이 틀렸단건 아닌데 그때의 나의 느낌을 좀 더 보정했어

- 먼저 후보, 문제 경계, 가능한 가치·성과·새 통제력을 충분히 펼친다.
- 펼치는 동안에도 사실 모순, 안전·비용·공식 경계, 개별 주장 상한은 엄격하게 본다.
- 근거 부족이나 한 편의 성립 기준으로 후보 전체를 닫는 판단은 충분히 펼친 뒤에 한다.
- 핵심은 `펼치고 거른다`를 넘어서 가치 발견, 주장 판정, 후보 수렴이 서로 다른 시점과 권한을 갖는다는 데 있다.
- 이 판단을 당시 사용자가 이미 같은 문장으로 의식했는지는 기억이 불확실하다. 원자료의 actor를 따르고 확인되지 않은 과거 1인칭 신념을 만들지 않는다.

기존의 `먼저 펼치고 거른다`는 이해를 폐기한 것이 아니다. 무엇을 먼저 펼치는지에 가능한 가치·성과·새 통제력을 명시하고, 발산과 주장 엄격함이 공존한다는 의미를 더한 보정이다.

### AI self-check

- 중심은 답을 다시 설명하는 일이 아니라, main의 문제 정의·전제·추상화·scope·도구 선택·다음 행동 자체를 검사 대상으로 만드는 일이다.
- 같은 판단 위치 안에서 반복 설명하거나 반대 방향으로 과교정할 때는 별도의 독립 판단 위치에 자신의 판단을 올린다.
- assignment와 AX 과교정, fresh auditor 운영은 다음 초안에서 다시 대조할 잠정 material 후보다. 종합 뒤 각 장면의 역할과 포함 여부를 정한다.
- forward bias 반복은 중요한 발동·실패 장면이지만 글 전체의 유일한 중심으로 고정하지 않는다.
- 다음 행동 차이는 self-check가 설명으로 끝나지 않았는지 보는 결과 기준이다. self-check의 본질 전체를 대신하지 않는다.
- 사용자는 결과를 조율하는 최종 판단자지만, `사용자가 조율한다`는 사실 자체가 이 글의 개념적 중심은 아니다.

독립 판별과 self-check를 두 편으로 나누는 현재 방향은 정했다. 두 글의 발행 순서와 구체적 연결 방식은 아직 열려 있다.

## 다음 초안 계약

1. 기존 v1~v3와 01~04 process는 수정하지 않는다.
2. 다음 초안은 기존 버전에 덮어쓰지 않는 새 cycle의 v1로 만든다.
3. 먼저 active-state, backlog, 1차 shaping, v1~v3, review와 반영 판단, 직접 원천을 종합한다.
4. 종합 결과에서 실제로 필요한 사실·의미·권위·해석 질문을 사용자와 풀어 중심을 맞춘다.
5. `blog-write`의 Material → Shaping → Texture 책임을 한 v1 안에서 수행하고 중간 판단은 새 process 묶음에 남긴다. material 단계를 draft 버전으로 세지 않는다.
6. 사용자 답과 위 작업을 종합해 직관적으로 판단 가능한 완결 초안을 만든다.
7. 독립 review는 유지한다. reviewer는 backlog·필요 원자료·해당 초안을 직접 보고 개선 기준과 backlog 활용 방식을 제시하며, main의 예상 문제나 원하는 결론을 정답처럼 받지 않는다.
8. reviewer 결과와 main 판단을 별도로 보존하고, v1 뒤 사용자와 다음 수정 범위와 버전 진행을 결정한다. 자동으로 v3까지 수렴하지 않는다.

## 아직 열려 있는 판단

- 새 cycle에서 어느 후보 또는 몇 편을 v1로 만들지
- 첫 글과 최종 article type
