# Current dual improvement review

이 cycle은 같은 Current 원고와 같은 직접 원천을 두 reviewer에게 주되, 개선 기준의 입력만 다르게 두어 결과를 비교한다.

- A는 블로그 editorial 기준과 이전 판단을 받지 않고, 현재 결과와 직접 원천의 차이에서 개선 기준을 새로 찾는다.
- B는 같은 결과와 직접 원천에 `product-architecture`, Shaping, developer, reader-flow, portfolio signal, voice, edit patterns의 관련 기준만 추가한다.
- 두 reviewer 모두 workspace의 `active-state`, 기존 `process`, 이전 원고와 review, 사용자가 이미 지적한 누락은 보지 않는다.

공통 독자는 내부 프로젝트 맥락을 모르는 긴 AI 협업 개발자다. 최소 성공 조건은 저자가 어떤 문제를 겪고 어떤 판단을 거쳐 운영 방식을 바꿨으며, 그 방식의 효용과 한계를 글만으로 따라갈 수 있는가다.

## 현재 경계

- 사용자가 A의 중심 변경 후보 제작을 승인해, `질문 범위와 시간축을 복구한 운영법`을 중심에 둔 structural candidate를 별도로 만들었다.
- B는 기존 중심과 대표 장면을 유지하는 local/partial edit 후보다.
- 이후 사용자 검토에서 두 후보 모두 `current`를 만든 이유와 발상 계보보다 Q1~Q5와 최근 문제 장면에 붙잡혀 있다는 공통 문제가 확인됐다.
- A의 제목과 일부 장면 배열은 더 생생한 비교 재료로 남지만, A와 B 어느 쪽도 현재 중심이나 다음 원고의 출발점으로 채택하지 않는다.
- 이 cycle의 review와 후보는 잘못 좁혀진 source packet과 최소 목표가 어떤 결과를 만드는지 보여 주는 시도로 보존한다.
- 어느 후보도 `src`의 현재 작업본을 교체하지 않는다.
