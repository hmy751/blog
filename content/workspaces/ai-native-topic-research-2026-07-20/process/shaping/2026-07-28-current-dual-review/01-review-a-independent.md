# A — source+result 독립 개선 review

## 입력 경계

A는 현재 Current 원고와 AX의 `current`, Loop 01 계약 분리, Q1~Q5 재작성, 제출 마지막 사건, current Git audit를 읽었다. Blog editorial 기준, workspace의 active-state와 process, 이전 원고·review, 사용자 피드백은 입력하지 않았다.

## 판정

A의 판정은 `structural rewrite`다.

현재 원고가 Q1~Q5 시간축 교정, 네 문서 역할, terminal gap을 비슷한 무게로 다뤄 중심 인과가 흐려졌다고 보았다. 권장 중심은 `current`라는 문서 구조보다 다음 운영 사건이다.

> 직전 작업이 프로젝트 전체를 덮었다. 저자가 질문 범위를 다시 나눴다. 전체 지도에서 맞는 높이와 원천을 찾아 답변을 다시 썼다. 이후 재진입 절차와 갱신 책임을 명시했다.

이 판단을 따르면 `current`는 글의 중심보다 범위 복구를 가능하게 한 장치가 된다.

## 주요 move

### Keep

- 최근 사실 자체가 아니라 전체 답변에서의 배치가 틀렸던 장면
- Q4와 Q5의 서로 다른 시간축
- 전체 지도와 단일 cursor
- `current`가 판단을 대신하지 않았다는 한계
- 마지막 제출·업로드 상태가 빠진 terminal gap
- 생산성 향상을 증명하지 못한다는 주장 상한

### Build

- 저자가 질문 범위를 다시 정한 인과
- `current`를 읽고 전체 그림과 현재 위치를 맞추는 재진입 절차
- 현재 계약과 과거 선택 이유를 분리한 한 사례
- 병렬 작업과 외부 사건 뒤 누가 current를 다시 합칠지 정하는 종료 책임

### Move / Cut

- `router` 판단을 첫 장면 가까이 이동
- 네 문서 역할은 절반 이하로 압축
- Q1~Q5 전체 표는 Q4/Q5 대비로 축소
- 판매자 질문 교정의 세부를 한 문장 수준으로 축소
- 내부 운영 용어는 `current`, cursor 외에는 역할어로 풀기

## Main이 바로 채택하지 않은 사실 제안

A는 지정 packet만으로 첫 답변 전에 AI가 `current`를 읽었다는 순서를 확인할 수 없다고 보고 문장을 삭제하자고 제안했다. Main이 설문 raw log를 좁게 대조한 결과, 해당 세션은 첫 답변 작성 전에 `context/current.md`를 읽고 프로젝트와 현재 cursor를 복기했다. 따라서 이 삭제 제안은 기각한다.

A는 Git audit만으로 verifier independence를 확인할 수 없다며 `독립 검증` 표현을 낮추자고 제안했다. 당시 직접 process 기록에는 기존 맥락을 주지 않은 별도 read-only 판별자의 입력과 독립 실행이 기록돼 있으므로, Git audit의 한계를 사건 전체의 미확인으로 확대하지 않는다.

추가 원천 `process/30`은 설문 재작성 중 다른 세션의 Loop 01 통과를 다시 읽어 Q5를 갱신한 순서를 지원한다.

## 사용자 판단이 필요한 지점

A가 제안한 다음 변경은 현재 중심과 사용자의 경험 해석을 바꾼다.

> `current`라는 active-state 구조를 글의 중심에 둘 것인가, 최근 맥락이 전체 프로젝트를 덮었을 때 질문 범위를 복구한 운영법을 중심에 둘 것인가.

A는 후자를 권장한다. 이 선택 전에는 A writer를 시작하지 않는다.
