# AI-native Quality Harness Research Guide

이 디렉토리는 `ai-native-topic-research-2026-07-20`에서 드러난 품질 실패와 이후 대화를 바탕으로, 다른 AI-native 작업에서도 실제 차이를 낼 수 있는 판단과 작동 방식을 찾고 시험하기 위한 독립 작업공간이다. `core`나 특정 하네스 형식을 만드는 것을 선행 목표로 두지 않는다.

## 작업 경계

- 원본 workspace `../ai-native-topic-research-2026-07-20/`는 읽기 전용 source로 취급한다.
- 원본 workspace의 `core/`, `active-state/`, `process/`, `sources/`, `src/`를 이 작업공간에서 수정하지 않는다.
- Current 원고, A/B 후보, 공개 초안도 수정하지 않는다.
- 이 작업공간의 결과는 원본 workspace나 다른 하네스에 자동 반영되지 않는다.
- 사용자가 수거 결과와 사례 검증을 본 뒤 채택 여부와 실제 owner를 결정한다.

## 현재 작업 방식

- 1·2차 발산 결과는 보존하되 후보 수를 더 늘리는 것을 진전으로 보지 않는다.
- 사용자 의도, 실제 실패 장면, 직접 source에서 해결할 문제와 필요한 변화부터 다시 잡는다.
- 공식 문서와 기존 하네스 조사는 가능한 위치·발동·권한·격리·검증 형식을 넓히는 비교 자료로 쓴다. 내용의 중요도와 채택을 결정하게 하지 않는다.
- 후보는 억지로 원자화하지 않는다. 하나의 후보 안에서 문제, 작동 원리, 발동 신호, 행동, 기대 변화, 관찰 증거, 한계를 함께 볼 수 있어야 한다.
- 서로 다른 후보를 같은 사례에 적용하거나 Current 밖 사례로 재생해 실제 판단·결과 차이를 비교한다.
- 반복 가치와 효용이 확인된 뒤에만 core, instruction, workflow, skill, agent, state, artifact, 사례 중 적절한 owner를 정한다.
- 사실·인용·Alex 관련 주장은 직접 원천이 확인한 범위를 넘기지 않는다.

## 디렉토리 역할

- `sources/`: 이 작업이 다시 접근해야 할 원문과 각 원천의 지원 범위
- `material/`: 사용자 의도, 관찰된 실패, 원인 후보, 사례 대조
- `candidates/`: 가능한 AI-native 패턴, 판단 감각, 대비 사례, 발동 상황
- `src/`: 현재 수렴 작업이 만드는 살아 있는 산출물. 첫 산출물은 해결 형식을 붙이지 않은 source 기반 문제 후보 지도다.
- `references/atomic-element-expansion/`: 첫 수거 시도에서 내용을 84개 하네스 요소 계약으로 원자화한 과거 확장 기록. 현재 채택 작업의 출발점으로 쓰지 않는다.
- `references/harness-form-catalog/`: 공식 문서와 일반 하네스 조사에서 내용이 아니라 담는 위치·발동·권한·검증 형식만 추출한 참고 카탈로그
- `synthesis/`: source와 확장 결과를 다시 연결해 실용 후보를 만들고, 비교·보류·검증·owner 판단을 수거하는 현재 작업면

`references/harness-form-catalog/`의 공식 제품 기능과 기존 조사 분류는 내용 권위가 아니다. `references/atomic-element-expansion/`의 원자 목록도 우선순위표가 아니다. 둘은 현재 `src/`를 역으로 채우는 입력이 아니라, source 기반 수거 뒤 누락과 구현 가능성을 점검하는 서로 다른 참고 자료다. 실제 채택은 source가 보여 주는 문제, 후보를 적용했을 때의 차이, 사용자 판단으로 결정한다.

## 상태와 권한

- 확장 단계의 후보는 현재 판단이나 사용자 합의가 아니다.
- agent와 reviewer의 제안은 제안 출처를 유지한다.
- 사용자의 경험·의도, 일반화 범위, 실제 하네스 반영은 사용자가 최종 결정한다.
- 사실 정정과 근거 경계는 main이 직접 확인해 반영할 수 있다.
