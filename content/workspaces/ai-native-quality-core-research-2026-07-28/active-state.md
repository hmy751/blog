# Active State

이 문서는 이 workspace의 전체 그림과 현재 판단점을 낮은 해상도로 보여 주는 재진입 지도다. 현재 단계만 요약하지 않고, 왜 시작했는지, 무엇을 펼쳤는지, 무엇이 어색하다고 판정됐는지, 다음에 무엇을 판단할지를 한 화면에 둔다.

상세 근거와 후보를 모두 여기로 옮기지 않는다. 직접 원천은 `sources`, 관찰과 원인 가설은 `material`, 넓게 펼친 패턴은 `candidates`, 계약 형태로 원자화한 후보는 `src`, 구현 형식 참고는 `src-reference-forms`, 전체 확장 지도와 이후 수거는 `synthesis`가 소유한다.

## 유지 원칙

- 이 문서에는 진행 cursor를 하나만 둔다.
- 완료된 큰 가지도 현재 판단을 이해하는 데 필요하면 접어서 남긴다.
- 사용자와 합의되지 않은 일반화는 현재 원칙처럼 쓰지 않고 `[열림]` 또는 `[보류]`로 표시한다.
- 상세 문서를 열지 않아도 현재 위치와 다음 판단을 알 수 있게 하되, 후보 전체를 이 문서에 복제하지 않는다.
- 형식 카탈로그가 내용의 중요도와 채택을 결정하지 않는다.

## 현재 지도

- 작업의 목적
  - Current 글 한 편의 복구 절차가 아니라, AI-native 작업에서 결과와 그 결과를 만든 판단 체계를 함께 개선하는 감각을 구체화한다.
  - 문제 해결뿐 아니라 사용자가 나중에 다시 읽고 자신의 판단과 역량을 복원할 수 있는 설명·대비·사례를 남긴다.
  - 글쓰기 사례를 보존하되 일반 AI-native 문제 해결이 우선이다.

- 출발한 품질 문제
  - Material과 동기는 있었지만 완결 결과와 review에서 반복해서 사라졌다.
  - A/B는 서로 다른 문장을 만들었지만 Q1~Q5와 최근 장면이 대표 문제라는 같은 frame을 공유했다.
  - 결과를 같은 goal·criteria·review 체계 안에서 계속 고쳐, 완성도는 올라가도 frame 자체의 품질은 다시 보지 못했다.
  - 사용자의 목적, 작업 가설, reviewer 제안, 현재 합의의 권위가 작업 중 섞였다.
  - 직접 장면과 대화 계보는 [원본 workspace](../ai-native-topic-research-2026-07-20/active-state/index.md), [사용자 의도와 품질 신호](./material/01-user-intent-and-quality-signals.md), [관찰된 실패 장면](./material/02-observed-failure-scenes.md)이 소유한다.

- 1차 발산
  - 17개 관찰 장면, 52개 경쟁 원인 가설, 50개 AI-native 패턴, 65개 개념 대비, 30개 발동 상황, 15개 전이 위험·반례 묶음을 만들었다.
  - Alex의 확인 사실·우리 해석·미확인 경계와 Current·AX·Alex 교차 비교를 분리했다.
  - [전체 확장 지도](./synthesis/01-expanded-landscape.md)는 반복되는 교차 질문과 아직 합치지 말아야 할 묶음을 보여 준다.

- 2차 발산
  - [src](./src/)에서 위 후보를 실제 하네스 요소라고 가정해 원칙·workflow·context·review·skill·artifact·learning의 84개 계약 후보로 원자화했다.
  - [10개 조립 구조](./src/08-assembled-harness-shapes.md)는 서로 다른 실패 가정에서 일부 요소가 어떻게 결합될 수 있는지 비교한다.
  - [src-reference-forms](./src-reference-forms/)에는 Codex·Claude 공식 문서와 기존 일반 하네스 조사에서 확인한 78개 구현 형식을 내용 후보와 분리해 뒀다.

- 현재 교정 `*-> 지금*`
  - 충분히 펼친다는 요구를 후보 원자 수를 늘리는 방식으로 과도하게 해석했다.
  - `src`에는 계약·발동·반환·오용 경계가 있어 빈 형식만 있는 것은 아니지만, 사고 과정과 실패 근거가 멀리 떨어지고 후보 간 위계가 없어 부품 카탈로그처럼 보인다.
  - 실제 효용과 반복 가치가 확인되지 않은 요소도 포함됐을 가능성이 높다.
  - 따라서 84개 요소를 하나씩 채택·탈락시키는 방식으로 바로 들어가지 않는다. 원자 목록은 확장 흔적과 하위 재료로 보존한다.
  - `src-reference-forms`는 구현 가능성을 넓게 보는 참고 카탈로그다. 내용의 중심·우선순위·채택을 결정하지 않으며, 수거된 내용의 owner를 정할 때만 다시 연다.

- 다음 수거 방향
  - 사용자 의도, 실패 장면, 여러 문서에서 반복되는 교차 질문으로 돌아가 서로 다른 메커니즘을 가진 큰 판단 묶음을 만든다.
  - 각 묶음에는 정의만 두지 않고 `어떤 실패를 설명하는가`, `무엇을 바꾸는가`, `언제 발동하는가`, `반례와 비적용 조건`, `사고를 복원할 사례`, `현재 합의 상태`를 함께 둔다.
  - 수거 지도에서 `거의 합의됨`, `일반화 후보`, `사용자 판단 필요`, `근거 부족·보류`를 구분한다.
  - 그 뒤에만 상시 유지할 얇은 원칙, 품질 정체 때 여는 상황별 route, 학습용 사례·대비, 버릴 후보를 나눈다.
  - 선택한 구조는 Current 사례와 글쓰기 밖 사례에서 재생한 뒤 원본 core 반영 여부를 판단한다.

## 현재 거의 합의된 방향

- 완결된 결과를 만드는 것과 결과를 만든 판단을 별도 위치에서 다시 보는 것은 양립한다.
- 완결 결과는 최종 답이면서 현재 goal·context·constraint·evaluation 체계가 만든 관찰물이다.
- 결과가 약할 때 모든 단계를 다시 감사하지 않고, 한 번 종합 판정한 뒤 실제로 문제를 만든 책임만 다시 연다.
- 같은 frame 안의 완성도와 frame 자체의 품질을 분리한다.
- source가 존재하거나 AI가 읽은 것과, source가 결과의 동기·중심·판단에 실제로 작동한 것을 구분한다.
- 여러 reviewer와 분석은 각자 다음 단계를 결정하지 않고 main이 회수한다.
- Alex의 표면 workflow를 복제하지 않고, 확인된 행동과 우리의 해석을 분리한다.
