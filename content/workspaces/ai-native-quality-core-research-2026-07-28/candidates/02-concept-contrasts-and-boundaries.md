# 개념 대비와 경계

이번 실패에서는 겉모양이 비슷한 개념을 같은 것으로 취급하면서 판단 위치와 권한이 섞였다. 이 문서는 “정답 용어집”이 아니라, 다음 작업에서 무엇이 다른지 다시 물을 수 있도록 대비를 넓게 보존한다.

## 결과와 작업 단위를 둘러싼 대비

### 산출물을 조각내기 / 판단을 분리하기

- **산출물을 조각낸다**: 초안, 기능, 문단, task를 여러 개의 작은 artifact로 나눈다.
- **판단을 분리한다**: 같은 완결 artifact를 두고도 탐색, 작성, 평가, 사실 검증, 사용자 승인 같은 판단 위치와 권한을 다르게 둔다.
- **다른 축**: artifact의 크기와 판단 주체·질문은 별개다.
- **오해 위험**: 판단 분리를 하려면 사용자가 모든 작은 조각을 승인해야 한다고 생각하는 것.
- **Current 근거**: 사용자는 완결 v1을 선호했고, 동시에 독립 review와 main adjudication을 원했다.

### 완결 / 수용

- **완결**: 요청한 형식과 범위에서 결과물이 끝까지 만들어졌다.
- **수용**: 사용자 목적과 품질 판단에서 다음 상태로 사용할 수 있다.
- **다른 축**: 제작 상태와 결정 권한.
- **오해 위험**: `PASS`, `final`, `near-final`이 수용을 자동 의미한다고 보는 것.
- **Current 근거**: A 후보는 구조와 사실 경계를 통과했지만 채택되지 않았다.

### 완결 / 최종 polish

- **완결**: 관계와 전체 인상을 판단할 만큼 통합돼 있다.
- **최종 polish**: 문장, 시각, edge case, 공개 준비까지 마쳤다.
- **다른 축**: 판단 가능성과 발행·배포 준비도.
- **오해 위험**: 완결 결과를 probe로 만들자는 말을 production-ready로 만들자는 지시로 확대하는 것.
- **Alex 근거**: 약한 해결책 판정에는 중간 solution report가 충분했다.

### 결과 / probe

- **결과**: 실제 사용하거나 제출할 산출물.
- **probe**: 현재 goal·context·constraints·evaluation이 어떤 결과를 만드는지 보기 위한 관찰물.
- **다른 축**: artifact 형태가 아니라 이번 cycle에서 맡는 역할.
- **오해 위험**: probe이므로 품질이 낮아도 된다고 하거나, 결과이므로 학습 재료로 볼 수 없다고 하는 것.
- **경계**: 같은 artifact가 두 역할을 동시에 가질 수 있다.

### output-first / solution 조기 고정

- **output-first**: 문제와 평가 기준을 더 잘 판단하기 위해 비교 가능한 결과를 먼저 만들어 본다.
- **solution 조기 고정**: 첫 구체 결과가 생겼다는 이유로 문제와 해결 방식을 닫는다.
- **다른 축**: output을 관찰물로 쓰는지, 권위 있는 답으로 쓰는지.
- **오해 위험**: AI가 싸게 생성할 수 있으니 나온 첫 결과를 계속 수정하는 것.

### version 증가 / 품질 학습

- **version 증가**: v1, v2, v3처럼 결과 수가 늘고 국소 개선이 생긴다.
- **품질 학습**: 새 결과를 통해 어떤 판단이 틀렸고 다음 cycle에서 무엇이 달라지는지 안다.
- **다른 축**: 반복 횟수와 판단 변화.
- **오해 위험**: iteration을 많이 했다는 사실을 loop가 잘 작동했다는 증거로 보는 것.

## 목적, goal, 기준을 둘러싼 대비

### 사용자 목적 / 현재 작업 goal

- **사용자 목적**: 이 작업으로 궁극적으로 얻으려는 비교적 안정적인 가치와 방향.
- **현재 작업 goal**: 이번 cycle에서 만들거나 판단할 구체적 결과.
- **다른 축**: 안정성, 범위, 변경 권한.
- **오해 위험**: 현재 결과가 약하다는 이유로 사용자 목적을 낮추거나, 상위 목적을 모든 국소 작업의 직접 acceptance로 쓰는 것.

### 현재 작업 goal / 작업 가설

- **현재 작업 goal**: 무엇을 만들어 어떤 상태에 도달하려는가.
- **작업 가설**: 어떤 중심·장면·solution이 그 goal에 이를 것이라고 현재 시험하는가.
- **다른 축**: 목표 상태와 그 상태에 이르는 잠정 설명.
- **오해 위험**: Q1~Q5 같은 대표 장면 가설을 Current 글의 목적 자체로 고정하는 것.

### 작업 가설 / 성공 조건

- **작업 가설**: 이 방향이 좋을 것이라는 잠정 선택.
- **성공 조건**: 결과를 보고 무엇이 충족되면 가설을 유지하거나 바꿀지 판단하는 기준.
- **다른 축**: 생성 방향과 평가 계약.
- **오해 위험**: 가설 자체의 특징을 성공 조건으로 넣어 자기검증하게 하는 것.

### goal 개선 / goalpost 이동

- **goal 개선**: 결과가 드러낸 실제 결함을 바탕으로 상위 목적을 더 잘 달성하도록 goal이나 success condition을 명료화·상향·재구성한다.
- **goalpost 이동**: 실패한 결과를 통과시키기 위해 기준을 사후에 낮추거나 다른 목표였다고 재서술한다.
- **다른 축**: 변화가 상위 목적을 더 잘 보존하는지, 결과를 정당화하는지.
- **판별 질문**: 무엇을 유지했고, 왜 바꿨고, 바뀐 기준이 더 엄격하거나 설명력이 높아졌는가.

### result correction / criteria update

- **result correction**: 현재 결과를 기존 기준에 더 잘 맞춘다.
- **criteria update**: 결과를 본 뒤 무엇을 좋다고 볼지, 무엇을 검사할지 자체를 개선한다.
- **다른 축**: 변경 대상.
- **오해 위험**: 모든 결과 오류를 criteria 문제로 올리거나, 기준이 결과 때문에 절대 바뀌면 안 된다고 보는 것.

### constraint / success condition

- **constraint**: 시간, 비용, 안전, 형식, 범위를 제한한다.
- **success condition**: 무엇이 충족되면 가치 있는 결과인지 판단한다.
- **다른 축**: 가능 공간을 제한하는 조건과 결과를 판정하는 조건.
- **오해 위험**: 짧은 시간 안에 만들 수 있다는 사실을 좋은 solution의 조건으로 쓰는 것.
- **Alex 근거**: 3~6시간 제약이 해결책의 야심을 줄였고, 이후 제약과 평가 기준이 함께 바뀌었다.

### 기준의 내용 / 기준의 시점과 권한

- **기준의 내용**: 무엇을 좋거나 나쁘다고 볼 것인가.
- **기준의 시점과 권한**: 언제 어떤 대상을 보고 무엇을 닫거나 바꿀 수 있는가.
- **다른 축**: 정당한 판단축과 그 적용 계약.
- **오해 위험**: 좋은 기준이면 어느 단계에서 어떤 권한으로 써도 좋다고 보는 것.

### criteria seed / filter / guard

- **seed**: 가능성을 생성하도록 문제와 관점을 여는 질문.
- **filter**: 펼친 후보를 비교·선택하는 기준.
- **guard**: 탐색 중에도 넘지 않아야 하는 사실·안전·비용·공개 경계.
- **다른 축**: 생성, 비교, 즉시 중단.
- **오해 위험**: filter를 seed로 주어 후보가 모두 닮게 만들거나, 발산을 이유로 guard까지 늦추는 것.

### 탐색 / 느슨함

- **탐색**: 후보, 문제 경계, 가능한 가치와 성과를 넓게 만든다.
- **느슨함**: 사실 오류, 안전 위험, 비용 한계를 검사하지 않는다.
- **다른 축**: 후보 공간의 개방성과 개별 주장의 엄격함.
- **경계**: 후보 전체를 닫지 않으면서도 각 주장에는 엄격할 수 있다.

### 수렴 / 압축

- **수렴**: 충분히 펼친 후보에서 목적에 맞는 방향을 선택하고 버릴 것을 결정한다.
- **압축**: 표현량, 사례 수, 문서 길이를 줄인다.
- **다른 축**: 의사결정과 정보량.
- **오해 위험**: 짧아졌으니 중심도 선명해졌다고 보거나, 후보를 선택했으니 material을 모두 삭제하는 것.

### 종합 / 압축

- **종합**: 서로 다른 source와 판단을 관계가 보이도록 함께 해석한다.
- **압축**: 중복과 세부를 줄인다.
- **다른 축**: 관계 구성과 정보 제거.
- **Current 근거**: v3는 정확하고 짧아졌지만 살아 있는 material 일부가 함께 줄었다.

## Source와 context를 둘러싼 대비

### source 보유 / source 작동

- **source 보유**: 파일이나 packet에 자료가 존재하고 agent가 읽었다.
- **source 작동**: 자료가 중심, 구조, 평가 질문, 다음 행동 가운데 하나를 실제로 바꿨다.
- **다른 축**: 접근 가능성과 판단 영향.
- **오해 위험**: source 목록이 길면 충분히 반영됐다고 보는 것.

### source coverage / 결과에 모두 포함

- **source coverage**: 필요한 사실·동기·대비를 판단할 수 있는 직접 원천 범위를 갖는다.
- **결과에 모두 포함**: source 내용을 원고나 출력에 최대한 넣는다.
- **다른 축**: 판단 가능성과 content 양.
- **오해 위험**: source-driven 개선을 coverage checklist나 전체 복사로 바꾸는 것.

### source / source에 대한 해석

- **source**: 사건, artifact, 사용자 원문, 공식 contract처럼 직접 확인할 근거.
- **해석**: source를 연결해 만든 의미, 중심, 인과, 적용 교훈.
- **다른 축**: 사실 권위와 판단 가설.
- **오해 위험**: 최신 해석 문서를 원천처럼 취급하거나, source가 있으니 해석도 자동으로 참이라고 보는 것.

### source packet / source universe

- **source packet**: 이번 역할에 제공한 선별 묶음.
- **source universe**: 접근 가능한 전체 직접 원천과 그 밖의 알려진 접근점.
- **다른 축**: 실제 입력과 가능한 탐색 범위.
- **오해 위험**: reviewer가 packet 안에서 추가 source를 고를 수 있다는 이유로 universe까지 열려 있다고 생각하는 것.
- **Current 근거**: A/B packet과 source index가 모두 최근 Current frame 안에 있었다.

### 최소 context / 적합한 context

- **최소 context**: 불필요한 anchor와 비용을 줄인 작은 입력.
- **적합한 context**: 그 역할이 판정할 질문에 필요한 motive·contract·source를 포함한 입력.
- **다른 축**: 양과 역할 적합성.
- **오해 위험**: 적을수록 독립적이고 많을수록 정확하다는 단일 규칙.

### blind / independent

- **blind**: 특정 이전 결과, 사용자 피드백, 작성 과정 등을 의도적으로 보지 않는다.
- **independent**: main과 다른 판단 위치, source 접근, 질문 수정, write·완료 권한을 가진다.
- **다른 축**: 정보 차단과 판단 계약.
- **오해 위험**: 원고만 보면 자동으로 독립 reviewer가 된다고 보는 것.

### fresh / source-free

- **fresh**: 기존 결과나 taxonomy의 anchor를 줄이고 다시 판단한다.
- **source-free**: 직접 원천과 기존 합의까지 보지 않는다.
- **다른 축**: prior artifact 차단과 근거 제거.
- **오해 위험**: fresh pass가 매번 사용자 목적과 backlog를 재학습하게 만드는 것.

### 현재 그림 / 과정 기록

- **현재 그림**: 지금 함께 작업할 전체 구조, 유효한 판단, 열린 질문, cursor.
- **과정 기록**: 그 판단이 만들어지고 바뀐 이유, 시도와 이전 결과.
- **다른 축**: 현재 권위와 시간순 복구.
- **오해 위험**: process를 active-state처럼 계속 갱신하거나 active-state에 모든 역사를 넣는 것.

### current / 요약문

- **current**: 전체 지도, 현재 한 점, 권위 원천과 재진입 경로를 연결하는 active control surface.
- **요약문**: 과거 내용을 짧게 줄인 설명.
- **다른 축**: 현재 작업을 제어하는 역할과 정보 압축.
- **오해 위험**: recent summary를 current로 부르거나 current에 모든 답을 넣는 것.

### 최신 / 현재 권위

- **최신**: 가장 최근에 생성·수정된 artifact.
- **현재 권위**: 지금 이 판단에서 따라야 할 contract나 사용자 합의.
- **다른 축**: 시간과 역할.
- **오해 위험**: 최신 review나 v3가 버전 번호 때문에 현재 판단을 자동 덮는 것.

### 최근 사실 / 전체 시간축에 맞는 답

- **최근 사실**: 지금 구현이나 마지막 사건에 대해 정확한 정보.
- **전체 시간축에 맞는 답**: 질문이 프로젝트 전체·현재 구현·선택 이유 중 어느 범위를 묻는지에 맞는 정보.
- **다른 축**: 사실 정확성과 질문 범위 적합성.
- **Current 근거**: Q1~Q5 답은 최근 사실이 틀렸다기보다 전체 질문에 배치된 시간축이 틀렸다.

### rule 품질 / activation channel

- **rule 품질**: 규칙의 내용이 타당하고 명료하다.
- **activation channel**: 필요한 결정 순간에 그 규칙이 읽히고 작동한다.
- **다른 축**: 문서 내용과 실행 경로.
- **오해 위험**: 같은 오판이 반복될 때 규칙 문장만 더 쓰는 것.

### 보존 / 현재 권위 / 매회 실행 / 함께 교체

- **보존**: 나중에 참고하거나 재검토할 가치가 있다.
- **현재 권위**: 지금 따라야 한다.
- **매회 실행**: 모든 cycle의 필수 check다.
- **함께 교체**: 한 artifact가 바뀌면 같이 갱신해야 한다.
- **다른 축**: 기억, 통제, 비용, lifecycle.
- **오해 위험**: 한 번 유용했던 fixture와 review를 모두 mandatory live context로 올리는 것.

## Review와 판정을 둘러싼 대비

### reviewer 수 / 독립된 판단 위치

- **reviewer 수**: 몇 개 agent나 사람이 결과를 봤는가.
- **독립된 판단 위치**: 입력, source, 질문, 권한, 회수 구조가 얼마나 다른가.
- **다른 축**: 실행 개수와 오류 상관.
- **오해 위험**: 세 agent가 같은 prompt를 받으면 세 독립 증거라고 세는 것.

### 다른 editorial 기준 / 다른 문제 frame

- **다른 editorial 기준**: 같은 중심과 source를 voice, flow, structure 등 다른 lens로 본다.
- **다른 문제 frame**: 무엇이 문제인지, 어떤 source와 질문이 대표인지부터 다시 본다.
- **다른 축**: 평가 렌즈와 평가 대상 정의.
- **Current 근거**: B는 global editorial 기준을 썼지만 goal과 source frame을 바꿀 권한이 없어 기존 중심 안에서 개선했다.

### reviewer 동의 / 상관된 결과

- **reviewer 동의**: 서로 다른 근거와 판단 경로에서 같은 결론에 도달했다.
- **상관된 결과**: 같은 packet과 frame 때문에 유사한 결론이 재생산됐다.
- **다른 축**: 결론의 유사성이 아니라 경로의 독립성.
- **오해 위험**: 다수결을 곧바로 객관성으로 올리는 것.

### reviewer / verifier

- **reviewer**: 더 나은 결과의 기준, 간극, 구조와 중심 후보를 본다.
- **verifier**: 좁은 주장과 직접 원천의 일치 범위를 본다.
- **다른 축**: 개선 판단과 사실 판정.
- **오해 위험**: verifier의 사실 오류가 후보 전체를 폐기하거나 reviewer가 사실을 추정하게 하는 것.

### reviewer / contextual editor

- **reviewer**: 현재 질문과 중심을 다시 열 수 있는 관찰을 만든다.
- **contextual editor**: 현재 합의와 중심 안에서 대안을 만들고 표현을 고친다.
- **다른 축**: frame을 재검사하는 권한.
- **오해 위험**: editor에게 독립 reviewer의 역할을 기대하거나 reviewer에게 중심 보호를 강제하는 것.

### reviewer / advisor

- **reviewer**: 특정 artifact와 판정 범위에서 개선·통과 조건을 반환한다.
- **advisor**: 큰 전환에서 빠진 관점과 경쟁 설명을 제공하지만 실행 결정을 소유하지 않는다.
- **다른 축**: 평가 대상과 조언의 범위.
- **오해 위험**: advisor의 넓은 가능성을 현재 결과의 verdict로 취급하는 것.

### review / adjudication

- **review**: 다른 판단 위치에서 관찰과 제안을 만든다.
- **adjudication**: 입력 경계, 현재 contract, 사용자 목적과 대조해 무엇을 채택·조정·기각·보류할지 정한다.
- **다른 축**: 새 차이를 만드는 역할과 현재 작업에 반영하는 역할.
- **오해 위험**: review가 곧 수정 명령이라고 보거나 main이 review 차이를 즉시 기존 언어로 지우는 것.

### 판정 완료 / 작업 완료

- **판정 완료**: reviewer가 자신의 범위에서 보고서를 끝냈다.
- **작업 완료**: main 회수, 필요한 사용자 판단, 실제 수정과 검증이 끝났다.
- **다른 축**: 역할 단위와 전체 workflow.
- **오해 위험**: agent status `done`을 사용자 목표 완료로 해석하는 것.

### local PASS / 전체 품질 PASS

- **local PASS**: 정해진 brief, 사실, 형식, test에서 조건을 충족했다.
- **전체 품질 PASS**: 사용자 목적과 결과 전체의 acceptance를 충족했다.
- **다른 축**: 판정 범위.
- **오해 위험**: 부분 PASS를 합산해 전체 PASS로 만드는 것.

### 사실 교정 / 장면·중심 변경

- **사실 교정**: source와 모순하는 actor, 순서, 수치, 구현 여부를 바로잡는다.
- **장면·중심 변경**: 어떤 사건이 무엇을 의미하고 글·제품에서 어떤 역할을 맡는지 바꾼다.
- **다른 축**: 사실 권위와 해석·사용자 경험 권한.
- **오해 위험**: 사실 하나의 오류로 사용자 경험 전체를 폐기하거나, 중심을 보호하려고 사실 교정을 미루는 것.

### 문제를 다시 열 권한 / 사용자의 목적을 바꿀 권한

- **문제를 다시 연다**: 현재 frame으로는 결과를 개선하기 어렵다는 관찰을 제시한다.
- **사용자의 목적을 바꾼다**: 무엇을 이루려는지 자체를 새로 정한다.
- **다른 축**: reviewer의 문제 제기와 최종 방향 결정.
- **오해 위험**: reviewer에게 질문 수정 권한을 주면 사용자 목적도 자유롭게 다시 쓸 수 있다고 보는 것.

## 합의와 권한을 둘러싼 대비

### 관찰 / 제안

- **관찰**: 입력에서 실제로 보인 강점, 간극, 누락.
- **제안**: 그 관찰을 바탕으로 무엇을 바꿀지 권하는 선택.
- **다른 축**: 증거 기술과 처방.
- **오해 위험**: 관찰이 정확하면 제안도 자동으로 맞다고 보는 것.

### 제안 / 적용

- **제안**: reviewer나 main이 권하는 방향.
- **적용**: 한 결과물이나 cycle에 실제 반영함.
- **다른 축**: 가능성과 실행.
- **오해 위험**: 적용했으니 장기 기준으로 합의됐다고 보는 것.

### 적용 / 사용자 합의

- **적용**: main이 다음 version에서 시험했다.
- **사용자 합의**: 사용자가 중심·경험·일반화 범위를 함께 결정했다.
- **다른 축**: 실험과 권위.
- **Current 근거**: `한 사건`, `한 artifact` 선택이 적용됐지만 고정 사용자 합의는 아니었다.

### 사용자 합의 / core rule

- **사용자 합의**: 현재 사례에서 함께 작업할 판단.
- **core rule**: 여러 cycle과 다른 사례에서 반복 적용할 판단축.
- **다른 축**: 적용 범위와 일반화 증거.
- **오해 위험**: 한 번 동의한 편집 선택을 workspace 전반의 반복 규칙으로 올리는 것.

### main의 위임된 국소 판단 / 사용자 결정 영역

- **위임된 국소 판단**: 사실을 바꾸지 않는 표현, 가역적 구현, 기계적 정리.
- **사용자 결정 영역**: 대표 장면, 큰 구조, 중심, 경험 해석, 공개 범위.
- **다른 축**: 결정의 영향과 위임 범위.
- **오해 위험**: provenance를 보존한다며 모든 micro decision을 사용자에게 묻거나, 속도를 이유로 중심까지 main이 정하는 것.

### human gate / manual micromanagement

- **human gate**: output이나 중요한 변화 지점에서 사람이 목적·taste·risk를 통합 판단한다.
- **manual micromanagement**: 모든 중간 재료와 기준을 작은 단위로 승인해야 한다.
- **다른 축**: 중요한 결정점과 상시 통제.
- **Alex 근거**: Alex는 약한 해결책에서 인간이 멈추고 제약과 평가를 바꿨지만 모든 생성 단계를 수동 승인한 것은 아니다.

## scope와 진행을 둘러싼 대비

### scope 축소 / 가치 경로 절단

- **scope 축소**: 데이터 종류, UI polish, 기능 폭을 줄이면서 핵심 가치를 end-to-end로 연결한다.
- **가치 경로 절단**: 핵심 변환을 fixture, raw response, 후속 spec으로 밀어 실제 사용자 변화가 사라진다.
- **다른 축**: 구현량과 causal path.
- **오해 위험**: vertical slice라는 이름만 붙으면 제품 중심이 보존됐다고 보는 것.

### 빠른 결과 / 쉬운 대체 결과

- **빠른 결과**: 작은 범위에서 실제 가치를 빨리 관찰한다.
- **쉬운 대체 결과**: 완료로 세기 쉬운 주변 artifact가 불확실한 핵심 작용을 대신한다.
- **다른 축**: 속도와 가치 적합성.
- **오해 위험**: 속도가 빠르면 회피이고 느리면 본질적이라고 단정하는 것.

### artifact 증가 / 작업 진전

- **artifact 증가**: 문서, test, review, dashboard, harness가 많아진다.
- **작업 진전**: 사용자 목적에 가까워지거나 중요한 불확실성이 줄어든다.
- **다른 축**: 산출량과 가치·학습.
- **오해 위험**: artifact를 모두 낭비로 보거나 수량을 생산성으로 보는 것.

### rollback / 전체 restart

- **rollback**: 잘못된 선택이나 책임 위치 전까지 돌아가 다른 선택을 시험한다.
- **전체 restart**: source, goal, 구현, 평가를 모두 처음부터 다시 한다.
- **다른 축**: 복구 지점.
- **오해 위험**: 근본 원인을 찾겠다는 이유로 매번 전체 작업을 폐기하는 것.

### 관련 책임 재개방 / 모든 단계 재실행

- **관련 책임 재개방**: 간극을 만든 Material, shaping, source frame, evaluation 등 특정 판단을 다시 본다.
- **모든 단계 재실행**: 정해진 workflow를 처음부터 끝까지 반복한다.
- **다른 축**: 원인 기반 대응과 절차 기반 대응.
- **오해 위험**: `Material로 돌아가기`를 모든 품질 실패의 기본 해법으로 만드는 것.

### 한 번의 오류 / 반복되는 판단 패턴

- **한 번의 오류**: 국소 correction으로 해결될 수 있는 단발 오독.
- **반복되는 판단 패턴**: 같은 판단 위치나 frame이 여러 결과에서 같은 종류의 어긋남을 만든다.
- **다른 축**: 발생 횟수보다 인과 구조의 재현.
- **오해 위험**: 첫 오독부터 self-check·advisor·fresh reviewer 전체를 호출하는 것.

### iteration / 자동 loop

- **iteration**: 결과를 보고 다음 행동을 선택하는 한 번의 반복.
- **자동 loop**: 정해진 agent와 평가가 stopping condition까지 자율 반복한다.
- **다른 축**: 반복 자체와 실행 권한·자동성.
- **Alex 경계**: 인간 주도의 solution concept 개선 iteration은 확인됐지만 final autonomous loop 완료는 확인되지 않았다.

## self-check와 학습을 둘러싼 대비

### 자기 설명 / 자기 판단 검사

- **자기 설명**: 왜 그런 답을 냈는지 현재 frame 안에서 해설한다.
- **자기 판단 검사**: 문제 정의, source 선택, 전제, scope, tool, 다음 행동을 별도 판별 대상으로 올린다.
- **다른 축**: 설명 대상.
- **오해 위험**: 긴 반성문을 self-check 성공으로 보는 것.

### 진단 정확성 / 행동 변화

- **진단 정확성**: 원인을 설득력 있고 근거 있게 설명한다.
- **행동 변화**: 다음 tool call, plan, artifact가 실제로 달라진다.
- **다른 축**: 언어 결과와 실행 결과.
- **오해 위험**: 정확한 진단이 자동으로 행동을 바꾼다고 보는 것.

### 행동 변화 / 재발 방지

- **행동 변화**: 한 번의 다음 선택이 달라졌다.
- **재발 방지**: 비슷하지만 다른 상황에서도 판단축을 복원한다.
- **다른 축**: 즉시 효과와 전이·안정성.
- **오해 위험**: 한 번 잘 고친 뒤 protocol 효과를 입증했다고 말하는 것.

### 학습 기록 / prescriptive checklist

- **학습 기록**: 정의, 근거, 대비, 발동 신호, 반례, 열린 질문으로 판단을 복원한다.
- **prescriptive checklist**: 정해진 순서와 항목을 매번 수행한다.
- **다른 축**: 판단 역량과 절차 준수.
- **오해 위험**: 학습을 남긴다는 이유로 모든 상황에 같은 workflow를 강제하는 것.

### 사례 전이 / workflow 복사

- **사례 전이**: 원본에서 확인한 판단 변화와 조건을 현재 문제에 맞게 해석한다.
- **workflow 복사**: 파일 구조, 단계, 수치, rubric을 그대로 가져온다.
- **다른 축**: 메커니즘과 표면 형식.
- **Alex 경계**: scaffolding과 제약 재평가 감각은 참고할 수 있지만 1~2주, virality, visual appeal은 일반 규칙이 아니다.

### 일반화 / 구체성 제거

- **일반화**: 다른 사례에서도 같은 판단축을 복원할 수 있도록 공통 메커니즘과 경계를 찾는다.
- **구체성 제거**: 사례의 조건, 실패 장면, 대비를 지우고 추상 문장만 남긴다.
- **다른 축**: 전이 가능성과 정보 손실.
- **오해 위험**: “본질” 한 문장으로 압축하면 더 일반적이라고 보는 것.

### core / process

- **core**: 반복해 물을 판단축과 적용 경계를 유지한다.
- **process**: 왜 그 판단이 생겼고 어떻게 바뀌었는지 실제 사례와 시행착오를 보존한다.
- **다른 축**: 재사용 판단과 시간순 근거.
- **오해 위험**: core를 모든 사례의 복사본으로 만들거나 process를 현재 rule처럼 사용하는 것.

## scaffolding과 loop를 둘러싼 대비

### scaffolding / plan

- **scaffolding**: 역할, context, 권위, 재진입, 공통 절차처럼 여러 실행을 지지하는 구조.
- **plan**: 이번 작업에서 수행할 구체적 행동 순서.
- **다른 축**: 반복 구조와 현재 실행.
- **오해 위험**: 상세 plan 하나를 장기 scaffolding으로 고정하는 것.

### scaffolding / quality loop

- **scaffolding**: output을 만들고 이어갈 환경을 구성한다.
- **quality loop**: output을 보고 결과·goal·constraints·evaluation 가운데 무엇을 바꿀지 판단한다.
- **다른 축**: 사전·지속 구조와 결과 기반 학습.
- **오해 위험**: scaffolding이 있으면 품질이 보장되거나 loop가 있으면 context가 필요 없다고 보는 것.

### scaffolding 변경 / 새 층 추가

- **scaffolding 변경**: 반복 오류와 연결된 기존 역할·권위·trigger를 고친다.
- **새 층 추가**: 새 문서, agent, status, check를 하나 더 만든다.
- **다른 축**: 원인에 맞는 수정과 구조 증가.
- **오해 위험**: 모든 품질 실패를 새 하네스 artifact로 해결하는 것.

### current의 갱신 / history의 보존

- **current 갱신**: 지금 유효한 그림과 cursor를 최신 판단으로 덮어쓴다.
- **history 보존**: 이전 선택과 변화 이유를 남긴다.
- **다른 축**: live control과 복구 가능성.
- **오해 위험**: history를 지우거나 current를 누적 로그로 만드는 것.

## 현재 대비 지도가 경계하는 과교정

- 완결본을 선호한다는 이유로 모든 탐색을 production-ready로 만들지 않는다.
- 판단을 분리한다는 이유로 사용자가 조각마다 승인하게 하지 않는다.
- goal을 개선할 수 있다는 이유로 실패한 결과에 맞춰 목표를 낮추지 않는다.
- 독립 review가 필요하다는 이유로 사용자 목적과 canonical source를 모두 숨기지 않는다.
