# AI-native 역량 글감 조사

이 폴더는 하나였던 조사 문서를 판단 기준의 변화와 현재 후보의 근거로 나눠 보존한다.

분리 전 732줄 조사 문서는 Git commit 435df83에 기준점으로 남아 있다. 분리하면서 후보의 중심 질문, 장면, 전개, 주장 상한, 제목 후보, source link를 축약하지 않는다.

## 공개 전 경계

이 폴더는 내부 source card다. 공개 원고로 옮길 때는 로컬 절대 경로, session·task ID, 비공개 대화 원문, 개인 ai-note 문장을 그대로 노출하지 않는다. 수치와 사건은 연결된 원자료에서 다시 확인하고, 공개 가능한 산출물·재현 절차·일반화한 장면으로 바꾼다.

## 문서

### [01-criteria-and-decision-history.md](./01-criteria-and-decision-history.md)

무엇을 좋은 AI-native 글감으로 보던 기준이 대화에서 어떻게 바뀌었는지 소유한다.

- 처음부터 유지됐어야 할 최상위 목적
- 예시·훅·준비도·레퍼런스·근거가 선택 기준으로 잘못 승격된 과정
- 사용자 정정 전후의 기준
- 최종 기준의 역할과 우선순위
- 폐기·보존·새로 생긴 기준
- 기준 변화가 각 후보에 미친 영향
- 닫힌 결정과 열린 편집 판단

### [02-topic-candidates.md](./02-topic-candidates.md)

현재 남은 다섯 후보를 상세히 소유한다.

- current / active-state operation
- 독립 판별 / 제3판별자
- 평가 기준을 적용하는 시점
- AI self-check
- 결과물 폐기와 기능 core 보존

각 후보에는 중심 질문, 새로 생긴 통제력, 대표 장면, 글의 전개, 아직 말할 수 없는 것, 제목 후보, 주요 원천을 남긴다.

## 현재 판단

- AI-native 관점의 대표성은 current가 가장 강하다.
- 기술 사례의 즉시성과 초안 준비도는 독립 판별이 가장 강하다.
- 두 후보가 서로 다른 기준에서 앞서므로 첫 글은 아직 확정하지 않았다.
- 평가 기준의 시점은 이번 조사에서 새로 선명해진 판단 감각이다.
- self-check는 성공 protocol이 아니라 열린 개인 탐구다.
- artifact/core는 제품 질문으로 선택적으로 돌아간 회고다.

## 다음 작업

첫 글을 결정하기 전에 current와 독립 판별을 각각 한 장으로 shaping한다.

각 한 장에는 다음을 둔다.

1. 첫 장면
2. 중심 질문
3. 시간순 본 사건
4. 독자가 볼 artifact
5. 사용자의 판단이 바뀐 지점
6. 다른 개발자가 가져갈 기준
7. 마지막에 남길 한계

그 두 장을 비교한 뒤 첫 글과 article type을 결정한다. 이 단계 전에는 고정된 시리즈 순서나 전체 초안을 만들지 않는다.
