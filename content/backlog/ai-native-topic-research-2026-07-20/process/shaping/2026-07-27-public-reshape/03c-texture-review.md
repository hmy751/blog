# Texture review

이 review는 중심을 새로 정하지 않고, public reshape가 살아 있는 장면·문장·발견·리듬을 평평하게 만들었는지 확인했다. 파일은 수정하지 않았다.

## 1. Current / active-state operation — PARTIAL

보호할 것:

- “완료 조건에도 만료 시점이 있었다.”
- 최근 구현 정보가 틀린 것이 아니라 프로젝트 전체 질문에 같은 해상도로 사용됐다는 판정
- “이번 판단은 직전 구현을 보는가, 프로젝트 전체를 보는가?”
- `current`가 판단을 대신하지 않지만 프로젝트 계보와 직접 source로 돌아갈 경로를 남긴다는 ending
- 외부 사건이 `current`에서 빠진 장면

평탄화 위험:

- first-pass의 가장 강한 장면은 `current`를 읽었는데도 최근 작업 하나가 프로젝트 전체가 된 순간이었다. v1은 이를 두 번째 장면으로 내리고 첫 화면을 계약·수명·권위 설명으로 채웠다. 대상은 구체화됐지만 발견의 순간은 설명 뒤로 밀렸다.
- v3의 current 활동 수치를 뺀 것은 품질 수치 오독을 막지만, 실제로 덮어쓰며 운영한 상태 artifact라는 촉감도 함께 약해졌다.
- primary table은 개념 분류에는 좋지만 실제 `current`의 전후 모습을 보여 주지 않는다. 네 상태가 살아 있는 운영물보다 잘 정리된 harness 표처럼 보일 위험이 있다.
- 전체 리듬은 `개념 정의 → 표 → stress test → 책임 → 원칙`으로 지나치게 반듯하다.

공개 독자 진입을 위해 제품 맥락을 먼저 둔 선택은 유효하다. 다만 실제 운영 흔적까지 지우면 `왜 만들 수밖에 없었는가`보다 `무엇인가`가 앞선다.

안전한 다음 edit:

- 중심은 바꾸지 않는다.
- 표 앞이나 다섯 문항 장면에 공개용 `current` 전후 4~6줄 예시를 복구한다.
- 내부 수치를 되살리기보다 실제로 계속 덮어쓴 상태였다는 작동 장면을 한 문장 남긴다.

## 2. Independent review — PASS

보호할 것:

- “9개 test가 답한 질문은 분명했습니다. 그 질문만으로는 제가 닫으려던 세계를 덮지 못했습니다.”
- 문자열 `"false"`가 변환 오류가 아니라 type contract를 비껴간 결함이라는 최소 재현
- 공개 source와 fixture의 모순
- 자연어 요청에서 다음 행동 변경까지 이어지는 E2E recovery
- “한 항목만 고치지 않고 제품 경로를 다시 열었다.”
- “제3판별자는 세 번째 AI가 아니었습니다.”

큰 평탄화는 없다. v3보다 저자의 `checkpoint를 닫지 않음 → 교정 범위를 정함 → 같은 제품 경로 재실행`이 선명해졌다. code, 비교표, E2E trace가 각각 다른 검증 경계를 맡아 living failure를 대체하지 않는다. 후반 reviewer governance는 다소 정리문처럼 읽히지만 닫힌 입력 밖을 못 본 반례가 이를 다시 구체화한다.

자료가 세 종류라 과밀해질 수 있지만 현재는 결함 재현, 검증 범위, 제품 재실행이라는 서로 다른 일을 맡는다. 줄이면 `test를 더 추가했다`는 평범한 글로 납작해질 가능성이 크다.

안전한 polish:

- artifact를 줄이지 않는다.
- reviewer 일반론의 반복만 압축하고, `"false"`, 잘못된 fixture, 자연어 E2E의 세 장면은 그대로 둔다.

## 3. Scope control — PASS

보호할 것:

- “하지만 그 화면에는 사용자가 물은 답이 없었습니다.”
- 검색 후보를 사용자가 다시 해석해야 했다는 구체적인 사용자 노동
- `15:00 / 16:00 / missing` 표와 값·근거·상태·다음 행동의 연결
- `source → answer → evidence/state → actual route → next action`
- 호출자 없는 fact 추출 경로를 제거한 구현 행동
- deterministic baseline과 product proof의 역할 구분
- 마지막 문장

v3의 두 경로 text diagram과 “검색 결과는 아직 사용자의 답이 아니었습니다”라는 단독 착지는 사라졌지만, v1의 첫 장면과 표가 그 역할을 대부분 보존한다. author agency는 `제안 → 채택하지 않음 → 계약 재정의 → test와 dead path 제거`로 살아 있다. artifact와 prose의 균형도 좋다.

후반부가 `일반 규칙으로 만들면 안 된다 → 역할에 따라 다르다 → 다음 기준`이라는 익숙한 AI 기술 글 ending으로 수렴하는 점은 남는다.

안전한 polish:

- 마지막 두 절의 일반화 문장만 더 압축할 수 있다.
- 표와 dead path 삭제 장면은 건드리지 않는다.

## 4. Judgment order — PARTIAL

보호할 것:

- `문제 3개 → solution 9개 → output 3개 → snapshot 9개 → 선택`의 실제 판단 지연
- 세 output에서 사용자가 바꿀 수 있는 것과 답변 뒤 보존되는 상태를 보여 주는 표
- 각 output의 구체 장면
- `엄격함의 유무가 아니라 엄격함이 갖는 권한`이라는 구분
- 실제로 두 번째 방향을 고른 이유와 맡지 않을 일
- 마지막 문장

평탄화 위험:

- near-final과 first-pass의 독특한 재료는 `판단 순서를 다루는 글을 고르면서 바로 같은 판단 순서를 어긴` 자기 재현 장면이었다. v1은 더 공개 친화적인 product output으로 시작하지만 이 재귀적 발견을 마지막 mirror로 압축했다.
- 글은 더 명료한 case study가 됐지만, 저자가 자기 작업에서 오류를 알아본 순간과 글 자체의 발견 리듬은 약해졌다.
- 세 output의 구체성은 강화됐으나 구조는 `수치로 범위 제시 → 표 → 방법 설명 → 주장 상한 → 선택 → meta mirror → 원칙`으로 정리돼 다른 기술 글과 닮아졌다.

product scene으로 시작한 선택은 독자 진입성과 독립 글 완결성을 높였다. 반대로 self-referential scene은 이 글만의 놀라움이었다.

안전한 polish:

- 중심을 바꾸지 않는다.
- 마지막 mirror에 `작업 cursor → 가치 순위`, `주장 상한 → 후보 감점`이라는 두 움직임을 한 호흡 더 남긴다.
- output 표나 실제 선택 장면은 줄이지 않는다.

## 5. AI self-check — PASS

보호할 것:

- 회사 자료와 사용자·독립 자료가 서로 다른 주장을 끝낸다는 첫 장면
- 유효한 정정을 적용하다 사용자 문제의 독립 경로가 사라진 과교정
- 세 상태 diagram
- “결론은 달라졌지만 판단축은 그대로일 수 있었다.”
- “‘더 근본적으로’를 ‘더 추상적으로’ 읽은 셈이었다.”
- 같은 전진 행동을 세 차례 멈춘 장면
- “문제를 설명하는 것과 다음 행동이 달라지는 것은 같은 결과가 아니었다.”
- 마지막 두 문장

first-pass에서는 forward bias 교정 대화에서 AI가 즉시 같은 행동을 재현한 사건이 가장 살아 있는 첫 장면 후보였다. v1은 이를 supporting scene으로 내렸지만 세 번의 제동과 실제 지침 변경을 남겨 질감 자체는 보존했다.

회사 조사 장면은 증명 범위와 판단축 언어가 조밀해 추상적으로 흐를 위험이 있으나 diagram과 assignment 역추적 장면이 이를 받친다. 세 사건이 framework 사례 목록처럼 보일 수 있지만 실패 모양이 달라 현재는 generic summary로 평평해지지 않았다. 했다체, `나는`, 짧은 마지막 착지가 다른 네 글과 구별된다.

supporting scene을 더 줄이면 first-pass의 생생한 실패가 사라지고, 같은 무게로 키우면 중심 사건이 흐려진다. 현재 위계를 유지할 가치가 있다.

안전한 polish:

- 사건은 줄이지 않고 사건 사이 설명형 연결만 다듬는다.
- 보호 문장과 마지막 두 줄은 유지한다.

## 전체 리듬과 ending — PARTIAL

다섯 편은 소재와 primary artifact는 구별되지만 네 기술 글의 큰 전개가 비슷하다.

```text
구체 기능 소개
→ 좁은 범위
→ AI의 그럴듯한 제안이나 판정
→ 저자의 중단과 재정의
→ 표
→ test 또는 contract
→ 한계
→ 다음 판단 기준
```

더 큰 문제는 ending이다. 내용은 다르지만 거의 모두 부정-교정형으로 닫힌다.

- Current: `더 많은 기록만이 아니었습니다.`
- Independent: `제3판별자는 세 번째 AI가 아니었습니다.`
- Scope: `작은 제품이 아니라 …`
- Judgment: `좋은 기준은 그 자체로 …`
- Self-check: `AI를 더 믿게 된 정도가 아니었다.`

공통 작성 계약이 피하려 한 `A가 아니라 B` cadence가 ending에서 다시 살아났다. 가장 안전한 다음 조정은 중심이나 결론을 바꾸는 것이 아니라 2~3편의 마지막 착지 역할을 달리하는 것이다. 한 편은 실제 다음 행동, 한 편은 남은 운영 책임, 한 편은 독자가 가져갈 질문으로 끝내고 대비형 ending은 가장 강한 글에만 남기는 편이 좋다.
