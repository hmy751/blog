# v1에서 v2로 갈 때 무엇을 반영할 것인가

이 문서는 [v1 독립 review 원문](./01-v1-independent-review.md)을 새 정답으로 올리는 문서가 아니다. reviewer의 지적을 원자료와 다시 대조한 뒤, v2에서 무엇을 채택·조정·기각·보류할지 main이 결정한 기록이다.

판정 표현은 다음 뜻으로 쓴다.

- **채택**: 제안한 문제와 수정 방향을 그대로 v2에 반영한다.
- **조정 채택**: 문제는 받아들이되, 글의 중심이나 질감을 지키기 위해 적용 범위를 바꾼다.
- **기각**: 현재 원자료나 글의 역할에 맞지 않아 적용하지 않는다.
- **보류**: 이번 버전에 바로 적용할 근거나 필요가 부족하다.

## 독립성 조건에 생긴 제한

reviewer는 backlog 검색 과정에서 제외하기로 한 이 draft-loop 폴더의 두 문서에서 일부 검색 일치 행을 보았다. 문서를 열거나 연속 본문을 읽지는 않았고, 노출된 내용은 경로·단계 상태·v1 링크·소제목 수준이었다.

이 시점의 draft-loop 문서에는 main의 v1 진단이나 reviewer에게 기대하는 기준이 없었다. `criteria-evolution.md`에도 active-state에서 가져온 v1 기준점과 빈 소제목만 있었다. 따라서 이번 report를 폐기할 정도의 내용 오염은 아니라고 판단한다. 다만 완전한 blind였다고 기록하지 않으며, v2의 두 번째 reviewer에게는 이 폴더 자체를 입력에서 물리적으로 빼는 방식으로 재발을 막는다.

## 공통 기준에 대한 판단

### 1. 중심 사건과 판단 변화 — 조정 채택

다섯 글 모두 중심 사건을 하나 정하고, 다른 사건에는 보조·반례·경계 중 하나의 역할만 준다.

다만 “한 글에는 사건 하나만 있어야 한다”는 형식 규칙으로 만들지는 않는다. `independent-review`의 Tripproof A/B와 `ai-self-check`의 AX 과교정처럼 중심 결론의 상한을 보여 주는 반례는 필요하다. v2에서는 사건 수보다 각 사건이 새 중심 질문을 열고 있는지를 본다.

### 2. 작은 before/after artifact — 조정 채택

독자가 글쓴이의 판단 변화를 복구하기 어려운 곳에만 재구성 artifact를 넣는다.

- current: 다섯 제출 문항이 담당한 시간축의 전후 배치
- 독립 판별: 9개와 15개 test method가 확인한 범위, 그리고 별도 설치형 E2E
- 판단 순서: 첫 후보판의 A1·A2가 두 번째 판에서 별도 비교 단위가 된 변화
- scope: 제안된 raw `facts[]` 경로와 실제로 구현한 `ChatAnswer` 소비 경로
- self-check: 설명을 고치는 동작과 자료 범위를 다시 확인한 동작의 대비

모든 글에 같은 표나 도식을 넣지 않는다. 내부 원문을 옮기지 않고, 역할과 순서를 다시 만든 자료임을 본문에서 밝힌다.

### 3. 사실·경험·해석·운영 규칙·미검증 효과의 현장 구분 — 채택

결말의 한계 문단만으로 중간의 강한 문장을 상쇄하지 않는다. 인과가 확인되지 않은 문장은 그 자리에서 `이 작업에서는`, `나는 이렇게 읽었다`, `운영 기준으로 삼았다`, `효과는 확인하지 못했다`처럼 범위를 드러낸다.

이는 새 editorial 축이 아니라 기존 active-state의 사실·경험·해석·모름 구분을 실제 산문에 적용하는 방식이다.

### 4. 제안·구현·실행 결과·장기 효과 분리 — 채택

이번 review에서 확인된 가장 중요한 사실 교정이다.

- raw `facts[]` 화면과 June 5 deterministic product slice는 구현 제안이었다.
- June 10의 metamorphic·grounding·routing test와 호출자 없는 경로 제거는 실제 구현이었다.
- entailment 판별 분리는 구현되고 A/B까지 실행됐지만 목표 acceptance는 불성립했다.
- current와 self-check 규칙은 실제 artifact지만 최근성 편향 감소나 재발 방지 효과는 측정되지 않았다.
- 판단 순서의 종료 조건은 현재 운영 규칙이지 품질 우월성이 입증된 방법론이 아니다.

v2뿐 아니라 사실 상태를 잘못 적은 first-pass shaping도 함께 고친다.

### 5. AI-native 장면은 남기고 모델 일반론은 낮추기 — 채택

다섯 글의 공통 가치는 일반적인 문서화·테스트·기획 조언이 아니라, AI와 작업할 때 생성과 판정의 문제 정의가 같은 맥락에 묶이고 권한 경계가 흐려진 장면에 있다.

이 장면은 보호한다. 대신 `AI는 늘`, `AI는 선호한다`, `오류 상관은 그대로다`처럼 관찰 범위를 넘는 문장은 해당 작업의 입력과 권한 배치에서 관찰된 현상으로 낮춘다.

### 6. 판단 장면을 체크리스트보다 보호하기 — 채택

각 글의 후반 목록은 하나의 도구로 모으고, 같은 내용을 다시 말하는 중간 목록은 장면이나 artifact로 바꾼다. 첫 오해, 망설임, 정정 뒤의 실제 행동, 마지막 판단 문장은 보호한다.

이는 “목록은 글당 하나”라는 새 금지 규칙이 아니다. v1에서 반복된 매뉴얼화 경향을 줄이기 위한 이번 수정 기준이다.

### 7. 공개 경계와 숫자 단위 — 채택

- private raw는 직접 발화가 아니라 행동 순서로 재구성한다.
- 내부 경로, line number, task·session 식별자를 공개 후보 초안에 넣지 않는다.
- 9와 15는 Python `unittest`의 test method 수이자 해당 runner의 실행 수라고 첫 언급에서 밝힌다.
- CLI, validator, 설치형 자연어 E2E는 이 숫자에 포함되지 않는 별도 검증이다.
- test 수와 commit 활동량을 품질·생산성·사용자 가치로 확대하지 않는다.

외부 상품 사실을 새로 구체화하지 않으므로 웹 전체 재조사는 하지 않는다.

## 글별 반영 판단

### `current-active-state-operation.md`

#### 채택

- 첫 장면을 “다섯 문항 전체가 최근 구현만 봤다”가 아니라, Q4의 전체 역할이 Q5의 최신 구현 시간축에 끌려간 사건으로 정확히 좁힌다.
- 사용자 정정 뒤 current와 context 계보를 다시 읽고, 병렬 Git·worktree의 최신 사실을 별도로 확인해 Q5를 갱신한 복구 순서를 넣는다.
- Q1~Q5가 각각 사용자 문제, 선택 근거, 제품 계약, 전체 AI·사람 역할, 최신 구현 검증을 맡도록 다시 배치한 before/after artifact를 넣는다.
- 설문 복구를 current 단독 효과로 쓰지 않는다.
- terminal event 누락 범위를 병렬 시간축에 맞게 고친다. 마지막 current가 고정될 때 설문은 이미 진행 중이었고, 최종 누락 범위에는 설문 완료, ZIP 검증, 업로드 실패와 후속 대응이 포함됐다.
- terminal event를 어느 writer가 반영할지 계약이 없었다는 ownership 문제로 한정한다. 실제 누락 원인은 기록만으로 정하지 않는다.

#### 조정 채택

history, active contract, source, current의 네 역할은 유지하되 중반의 반복 설명을 줄이고, 설문 재작성 사건과 terminal event 반례에 더 많은 공간을 준다. 네 역할은 결말의 운영 구조로 압축한다.

#### 기각

검증용 agent가 다른 current 규칙 때문에 잘못된 작업 위치로 들어간 별도 사례는 v2에 추가하지 않는다. 역할별 활성화라는 새 질문을 열어 중심 사건을 분산시키기 때문이다.

21개 reachable commit 중 current가 바뀐 횟수도 넣지 않는다. 이번 글의 판단을 복구하는 데 필요하지 않고 효용 지표로 오독될 수 있다.

#### 보존

- 전체 지도와 현재 cursor는 서로 대체할 수 없다는 설명
- current가 답 저장소가 아니라 권위 있는 source로 내려가는 router라는 해석
- current를 자동 context 주입 장치로 보지 않는 한계
- 생산성·연속성 효과를 주장하지 않는 결말

### `independent-review-and-recovery.md`

#### 채택

- 첫 checkpoint의 9와 교정 뒤 15를 `unittest test method`로 명시한다.
- plugin validator, CLI, 설치형 자연어 E2E는 9·15에 포함되지 않는 별도 검증이라고 밝힌다.
- 첫 미통과 상태를 “설치형 E2E가 없었다”로 뭉뚱그리지 않는다. plugin이 설치 목록에 없었고, 설치된 새 작업에서 자연어로 끝까지 실행한 증거가 없었다고 적는다.
- 티켓 claim 교정을 정확히 쓴다. 공개 source로 닫힌 티켓 절차는 seller claim에서 제거했고, 남은 시작 시각 claim에는 전체 plan scope를 요구했다.
- AX 사건을 글의 중심 척추로 유지하고, 9→15 변화는 숫자 증가가 아니라 fixture consistency, source-to-contract, adversarial schema, 설치형 자연어 E2E의 검증 역할 차이로 보여 준다.
- Tripproof는 분리된 judge의 성공 사례가 아니라 입력 경계 반례로 한정한다.
- Tripproof A/B의 결과를 정확히 고친다.
  - 한 문항은 의도한 조건 판정이 아니라 값 미추출 뒤 안전망으로 내려갔다.
  - 한 paraphrase는 retrieval candidate가 없어 judge가 실행되지 않았다.
  - 다른 paraphrase는 조건 문장을 값으로 추출해 `supported`가 누출됐다.
  - 기대-supported 하락 하나는 value grounding 회귀였고, 다른 하나는 실제 조건 문맥과 dataset 기대가 충돌한 경우였다.
  - 판별 분리와 response shape 보존은 확인됐지만 목표 acceptance는 불성립했다.
- `오류 상관이 그대로 남는다`는 문장을, 이번 A/B에서 별도 호출도 앞단에서 사라지거나 뒤바뀐 정보를 복구하지 못했다는 관찰로 낮춘다.

#### 조정 채택

read-only, 결과 분리, 사용자 회수, 완료 선언의 분리는 보존한다. 다만 보편적 독립 판별 방법론처럼 확장하지 않고, 두 사건 뒤에 선택한 운영 경계로 짧게 묶는다.

#### 보존

- “test가 거짓말을 한 것은 아니었다”는 중심 문장
- 첫 verifier가 이전 대화와 구현자의 완료 설명을 받지 않았지만 목표·계약·artifact에는 접근했다는 정확한 경계
- fresh regression이 외부 제출물 단독 재현이 아니었다는 한계
- reviewer 수나 모델 차이가 독립성·품질 향상을 자동으로 만들지 않는 결말

### `judgment-order.md`

#### 채택

- 블로그 후보 작업은 문제를 드러내는 첫 장면, AX는 경계 변화 artifact, Cofathon은 다른 환경에서 관찰된 반복과 혼재 변수로 역할을 나눈다.
- “같은 자료를 다른 순서로 봤다”는 통제 비교처럼 보이는 표현을 고친다. 기존 후보판을 직접 입력에서 제외한 별도 구성에서, 노출 조건이 다른 두 판의 묶음 경계가 달랐다고 쓴다.
- AX의 핵심 변화는 3개→5개라는 수가 아니라, 첫 판 안의 `객관적 실행 가능성`과 `실제 진행 경험 예상`이 둘째 판에서 별도 비교 단위가 된 것이라고 보여 준다.
- 둘째 판은 기존 후보를 처음 발견한 것이 아니며 완전 blind도 아니었다는 한계를 가까운 위치에 둔다.
- Cofathon에서는 첫 15개 업무·문제 후보 계열이 검증된 제품 후보가 아니었고, 별도 scene-first 재시작의 여섯 후보 문서에 actor, workflow, 입력·결과, 확인 수준이 명시됐다는 artifact 변화까지만 쓴다. 이 여섯 개는 선택되지 않은 1차 연구 산출물이며, 후기 MyRealTrip 계보의 5개·네 비교 후보+한 확장 가설과 연결한 수렴 숫자로 쓰지 않는다.
- `AI는 방어 가능한 답을 만든다`, `rubric에 맞는 후보를 선호한다`는 문장을 현재 작업에서 생긴 가설로 낮추거나 제거한다.
- 발산 종료 순서는 현재 목적과 비용 아래에서 쓰는 운영 규칙이라고 표시한다.

#### 보존

- 자기참조적인 첫 장면
- 생성·관찰, 주장 판정, 후보 수렴의 권한 분리
- 확인·불충분·모름·다음 확인 질문의 구분
- 모순과 고정 경계는 중간에도 후보를 종료할 수 있다는 설명
- second pass와 scene-first의 품질 우월성을 주장하지 않는 결말
- “엄격함이 무엇을 겨누는지 정한다”는 마지막 판단

### `product-flow-scope-control.md`

#### 채택

- raw `facts[]` 경로를 실제 화면이 아니라 구현 준비 중 나온 제안으로 고친다.
- June 5의 sanitized seed와 deterministic adapter도 첫 product slice로 삼자는 제안이었다고 고친다.
- 이미 존재했던 regex deterministic baseline 자체와 June 5의 새 product-proof 제안을 섞지 않는다.
- June 9 실제 구현은 raw fact를 앞면에서 제거하고 `/api/questions → ChatAnswer → 상태·inline evidence`를 연결한 쪽이었다고 보여 준다.
- June 10의 metamorphic·grounding·routing test와 호출자 없는 추출 경로 제거는 실제 구현 artifact로 구분한다.
- `AI는 작고 확실한 쪽으로 수렴했다`는 문장을, 이 대화에서 불확실한 중심 변환 대신 눈에 보이는 surrogate를 택한 제안으로 읽었다는 경험 해석으로 낮춘다.
- test가 의미 품질, 사용자 가치, 이후 drift 감소를 증명하지 않는다는 한계를 가까운 위치에 둔다.
- first-pass shaping의 같은 사실 오류도 함께 수정한다.

#### 조정 채택

라이브러리·배치·데이터 파이프라인 예시는 소비자 계약이 UI와 같지 않다는 경계만 남기고 압축한다. 중심은 `facts[]` 제안에서 실제 `ChatAnswer` 구현과 제품행동 test로 판단이 옮겨 간 사건이다.

#### 보존

- 범위의 폭과 제품의 핵심 작용을 구분한 설명
- deterministic 구현 자체가 항상 가짜는 아니라는 반대 경계
- slice의 끝은 UI가 아니라 실제 소비자 계약이라는 결말

### `ai-self-check.md`

#### 채택

- forward bias 사건을 중심 척추로 두고, 보존 기록의 범위를 정확히 쓴다. 전체 횟수는 3~4회로만 요약돼 있고, 기록에는 재발 지적 → 생각만 제시 → before/after만 제시하라는 세 중단 발화가 남아 있다.
- 보존 raw에 원인 설명 전문이 없으므로 `AI의 설명은 정확했다`는 화자 귀속을 낮춘다. 대화에서 정리된 문제와 사용자의 납득 범위로 쓴다.
- assignment archive 사건에서 사용자가 한 과제의 전제를 지적한 뒤 AI가 누락을 인정했고, 전체 재검색 지시 뒤 세 곳을 더 고친 실제 다음 행동을 보여 준다.
- 이 행동 변화는 formal self-check 이전에 사용자의 직접 정정과 재검색 지시로 생겼다고 밝힌다. self-check 효과로 사용하지 않는다.
- AX 과교정 복구는 사용자가 잘못된 적용을 다시 검출하고 더 넓은 대화 범위를 지정한 뒤, 두 번째 별도 점검이 원래 구조를 복구한 결합 사건으로 쓴다.
- fresh audit는 기존 문제 이름을 그대로 받지 않는 별도 판단 상태라는 경계까지만 남긴다. 독립 판별 글의 read-only·회수 계약을 반복하지 않는다.
- 후반 발동 기준은 `단순 질문 → 설명`, `첫 정정 → 바로 반영`, `같은 축 반복 → self-check 또는 별도 판별`로 압축한다.

#### 조정 채택

assignment archive는 self-check 정의의 발단, AX는 반대 방향 과교정 반례, 단순 질문은 과잉 발동 경계로만 쓴다. 사건을 삭제하지는 않되 중심 질문과 같은 무게를 주지 않는다.

#### 보존

- 진단 정확도, 다음 행동 변화, 재발 방지를 서로 다른 결과로 보는 중심
- 전역 규칙이나 skill 생성이 효과 증명이 아니라는 한계
- “설명과 행동을 같은 결과로 보지 않게 됐다”는 마지막 문장
- 회고의 `했다`체와 개인적 판단 질감
