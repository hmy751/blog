# 새 v1 독립 review main 판정

이 문서는 독립 reviewer와 evidence checker의 결과를 현재 사용자 합의, backlog의 권위, 실제 원고에 다시 대조해 `채택`, `조정 채택`, `기각`, `보류`로 판정한다.

독립 review가 시작된 뒤에는 v1 원고를 수정하지 않았다. 아래 채택 항목은 v1을 조용히 덮어쓰는 수정 지시가 아니라, 사용자가 다섯 원고와 review를 함께 본 뒤 v2로 갈 때 적용할 후보 판정이다.

## Evidence check 선판정

### 채택 — v2 전 필수 사실 교정

- AI self-check의 `대개`는 소수 사례를 빈도 주장으로 확대한 표현이므로 `이 작업들에서는`으로 낮춘다.
- 판단 순서의 상태 전환 수는 `세 출력에 걸쳐 총 여덟 번`으로 고친다.
- assignment 사건의 중간 AI 발언은 원문이 남아 있지 않으므로 정확한 당시 발언처럼 쓰지 않는다. 후대 기록의 해석임을 밝히거나, 원문으로 지지되는 `더 근본적 / 더 추상적` 발견만 남긴다.

### 조정 채택 — 보편 주장 대신 운영 정의로 낮춤

- `자기 frame 안에서는 자신의 판단도 객관적으로 보기 어렵다`는 문장은 모든 AI의 보편 특성처럼 두지 않는다.
- self-check의 정의를 `자기 frame 안의 판단을 곧바로 객관적이라고 가정하지 않는 방법`으로 바꾸면 현재 사례와 중심을 모두 보존할 수 있다.

### 채택 — public boundary 일반화

- Scope 글의 `facts[]`는 식별자 자체가 논증에 필요하지 않으므로 `검색 후보 목록` 또는 `검색·추출의 중간 결과`로 일반화한다.
- Current 글의 `Q4`, `Q5` 번호는 `프로젝트 전체 역할을 묻는 문항`, `최신 구현을 묻는 문항`으로 바꾼다. 시간축 대비는 유지한다.

### 보류 — 사용자 공개 판단

- `current.md`라는 이름은 글의 중심 개념과 제목을 함께 만든다. 경로와 원문은 노출하지 않아 위험도는 낮지만 실제 내부 파일명에서 출발했다.
- `현재 상태 문서`로 일반화할지, 반복 사용해 온 개인 운영 개념으로 `current.md`를 공개할지는 사용자가 v1을 읽고 결정할 항목으로 남긴다.

## 독립 reviewer 종합

두 reviewer는 서로의 report를 보지 않고도 다음에 합의했다.

- 다섯 편은 모두 독립 글로 살아 있다. 지금 병합·폐기하거나 한 편의 template로 다시 만들 이유는 없다.
- 중심과 주장 상한은 강해졌지만, 실제 판단 장면보다 그 판단을 정리한 운영 언어가 앞에 보이는 구간이 있다.
- 다음 pass는 backlog의 기준을 더 붙이는 일이 아니라, 현재 중심을 지키며 초기 backlog와 직접 원천에서 독자가 판단을 복구할 장면을 다시 꺼내는 일이다.
- 다섯 편의 surface rhythm, ending, 용어가 비슷해졌다. article type별 목소리와 산문 engine을 다시 분리할 필요가 있다.
- 독립 판별 글은 현재 가장 기술 사건과 판단 구조가 잘 맞물려 첫 공개 후보에 가깝다.

두 reviewer가 제안한 `각 글의 public-safe artifact 하나`는 전역 writing 기준으로 승격하지 않는다. 이번 다섯 원고를 대조했을 때 공통으로 확인된 구체 gap에 대한 처방이다. 글마다 독자가 판단 변화를 이미 복구할 수 있다면 artifact 수를 맞추기 위해 새 표나 code를 추가하지 않는다.

### Reviewer report 자체의 상한

- Reviewer A는 한 대목에서 `자연어 E2E 15개`처럼 읽힐 수 있는 표현을 사용했다. evidence check상 15는 Python `unittest` test method 수이며 자연어 E2E는 별도 검증이다. 이 표현은 채택하지 않는다.
- 두 reviewer가 제시한 공개용 pseudo-test와 표는 artifact 방향 제안이지 직접 원천 자체가 아니다. v2에서 쓰려면 실패 범주를 원천에 다시 대조하고 재구성 예시임을 밝혀야 한다.
- Reviewer B가 제안한 다섯 글의 공통 발견은 흥미로운 편집 해석이지만 공식 series thesis로 올리지 않는다. 다섯 글은 시간축, 검증 입력, 제품 인과, 기준 권한, 자기 판단축이라는 서로 다른 문제를 소유한다.
- Reviewer A의 `한 글에 하나의 주 사건` 제안도 고정 gate로 쓰지 않는다. 부 사건이 중심 발견을 전진시키는 역할이 있다면 남긴다.

## 공통 main 판정

### 조정 채택 — 판단을 복구하는 artifact

각 글에서 독자가 저자의 결론을 믿기만 하는지, 아니면 작은 전후 차이로 같은 판단을 복구할 수 있는지 본다.

- Current: 현재 계약과 history가 섞인 상태, 분리 뒤 권위와 갱신 경로의 차이
- 독립 판별: 실패 범주 하나의 입력·판정과 원자료 대조·재실행
- Scope: source 값이 바뀌거나 사라질 때 answer·state·다음 행동이 달라지는 모습
- 판단 순서: 기준이 너무 이른 시점에 잘못 겨눈 대상과 output 비교가 열어 준 차이
- Self-check: 같은 축의 양방향 과교정과 관계를 다시 구성한 세 상태

이는 “표를 하나씩 넣는다”는 뜻이 아니다. 산문, 작은 table, 재구성 code, state trace 중 글의 판단을 가장 짧게 보이게 하는 형식을 고른다.

### 채택 — 글별 article type과 ending 분리

- 독립 판별은 technical incident와 검증 경계를 충분히 따라간다.
- Scope는 용어와 반례를 줄인 짧은 product-architecture 글로 만든다.
- Current는 문서 종류 설명보다 상태의 read/write와 권위 이동을 보여 준다.
- 판단 순서는 비교 실험의 호기심과 발견을 남긴다.
- Self-check는 회고의 개인적 호흡을 회수한다.

다섯 글 모두를 `운영 질문 목록 → 완성된 계약`으로 닫지 않는다. 결말은 각 글이 실제로 확인한 변화와 남은 조건에 맞춘다.

### 채택 — backlog 역할 분리

- active-state와 사용자 sync는 중심·주장 상한의 guard다.
- source-first와 직접 원천은 장면·충돌·public-safe artifact를 찾는 곳이다.
- 초기 v1과 candidate 기록은 살아 있는 문장·망설임·발견을 찾는 곳이다.
- v2·v3는 actor, 숫자 단위, 제안·구현, 인과 범위를 교정한 장부다.
- review와 adjudication은 새 요구사항 목록이 아니라, 어떤 편집이 글을 평평하게 했는지 확인하는 판단 기록이다.

### 채택 — 한계는 주장 가까이에 한 번만

claim ceiling을 삭제하지 않는다. 다만 같은 방어를 본문과 결말에서 되풀이하지 않고, 제한할 주장 바로 옆에서 정확히 한 번 적용한다.

## 후보별 main 판정

### Current / active-state operation

**현재 중심 유지.** 실제로 도움이 된 active control을 먼저 보여 주고 Q4/Q5, 갱신 누락, 현재 블로그 재현은 작동 조건과 한계로 두는 배열이 맞다.

v2에서 채택할 move:

- process history 안에 살아 있는 완료 조건과 선택 이유가 함께 있었던 상태, active contract를 분리한 뒤의 권위 이동을 작은 before/after로 보여 준다.
- 현재 지도 예시는 전체 지도와 cursor의 비대체성을 보여 주는 역할로 남기되, 용어를 더 늘리지 않는다.
- Q4/Q5 번호는 공개 글에서 일반화하고, 사용자 정정 뒤 `current`가 복구 경로로 작동했다는 범위만 말한다.
- 현재 블로그 사례는 효과 증명이 아니라 현재 권위가 다시 풀린 재발·복구 장면으로 유지한다.

보류:

- `current.md`를 개인 운영 개념으로 공개할지 `현재 상태 문서`로 일반화할지는 사용자 판단이 필요하다.

### 독립 판별 / 제3판별자

**현재 다섯 편 중 첫 공개 후보로 가장 강하다는 판정에 동의한다.** 다만 발행 순서는 사용자가 정한다.

v2에서 채택할 move:

- AX 사건을 절대 중심으로 두고 `"false"` 또는 상반 claim 순서 의존 중 하나를 public-safe 최소 예시로 만든다.
- 판별 결과의 별도 보존과 회수를 추상 4단계로만 설명하지 않고, 한 항목의 `판별 → 원자료 대조 → 채택·제한 → 재실행`으로 보여 준다.
- 9·15 검증 역할 표와 설치형 자연어 E2E는 유지한다.
- 두 번째 answer system 반례는 `판정 역할 분리와 입력 경계 분리는 다르다`는 한계를 맡는 짧은 문단으로 줄인다.

채택하지 않을 표현:

- `15개 E2E`, `완전한 clean-room reviewer`, test 수 증가를 품질 향상으로 읽는 표현
- 실제 내부 code를 그대로 공개하는 artifact

### Scope control

**중심 유지, 제목과 public artifact는 재조정.**

v2에서 채택할 move:

- 체크인 시각이 `15:00 → 16:00 → 원문에 없음`으로 바뀔 때 값, `supported/missing`, 근거, 다음 행동이 어떻게 달라지는지 하나의 public-safe artifact로 보여 준다.
- 세 test는 그 artifact가 어떤 회귀를 막는지 설명하는 증거로 붙인다.
- deterministic baseline은 위험 격리와 product proof 대체가 다르다는 한 문단 경계로 줄인다.
- `facts[]`와 불필요한 내부 운용어는 일반 독자가 역할을 이해할 수 있는 말로 바꾼다.
- 현재 제목의 `왜`는 확인하지 못한 AI 의도·원인을 약속할 수 있으므로 관찰형 제목으로 낮춘다. 정확한 제목은 v2 작성 때 원고의 첫 장면과 함께 고른다.

유지할 상한:

- 두 초기 경로는 배포 실패가 아니라 구현 전 제안이다.
- 세 test는 semantic quality나 실제 사용자 가치 전체를 증명하지 않는다.

### 생성·주장 판정·후보 수렴의 판단 순서

**중심 유지, 재료 소유권은 v2 전 결정 필요.**

v2에서 채택할 move:

- 글감 연구에서 `작업 cursor → 가치 순위`, `주장 상한 → 후보 감점`으로 바뀐 오독을 bookend로 쓴다.
- AX의 세 output 비교 table은 현재 판단의 실험 근거로 유효하다. 수치와 부가 절차보다 어떤 사용자 판단과 통제력 차이가 보이게 됐는지에 분량을 쓴다.
- Cofathon은 같은 rubric 언어를 되비춘 짧은 반복 장면 이상으로 키우지 않는다.
- 세 단계는 만능 방법론이 아니라 조기 수렴을 막고 비교 전에 다른 차이를 보게 한 운영 순서로만 남긴다.

보류:

- 현재 별도 후보인 `Output-informed problem selection`과 AX의 `3 problem → 9 solution → 3 output → 8 transition` 재료를 누가 소유할지 결정해야 한다.
- main의 잠정 추천은 이 재료를 판단 순서 글의 중심 근거로 귀속하는 것이다. 별도 후보는 같은 사건을 반복하는 글이 아니라 output을 비교 대상으로 만드는 더 좁은 기술 질문과 독립 재료가 있을 때만 유지한다.
- 이는 유지 후보 하나의 위상을 바꾸는 결정이므로 사용자 review 전 active-state를 수정하지 않는다.

### AI self-check

**현재 중심 유지.** 다섯 편 중 개념적으로 가장 독창적이라는 reviewer 판정에도 동의한다.

v2에서 채택할 move:

- `회사 중심 → 사용자 중심 → 역할 관계 재구성`의 세 상태를 public-safe before/after artifact로 만든다.
- AX를 주 사건, assignment를 `더 근본적 / 더 추상적`의 보강 사건, forward bias를 진단·행동·재발이 다르다는 stress test로 유지한다.
- `main AI`는 처음 등장할 때 `작업을 조율한 주 AI`처럼 풀어 쓴다.
- 공개되지 않은 assignment 중간 답변을 정확한 당시 발언처럼 재구성하지 않는다.
- 보편적인 자기 객관화 실패가 아니라, 이 사례들 뒤 자기 판단을 곧바로 객관적이라고 가정하지 않게 된 개인 운영 변화로 닫는다.

조정 채택:

- retrospective 목소리를 구분하기 위해 했다체를 다시 시험할 가치가 있다. 다만 단순 어미 일괄 변환이 아니라 이전 v1의 살아 있는 자기 관찰을 참고해 v2에서 한 번에 읽어 본 뒤 결정한다.
- trigger 목록과 독립 판별 연결은 개념을 운영 manual로 넓히지 않는 범위에서 더 줄일 수 있다.

## 다음 버전에 적용하지 않을 것

- 다섯 편을 하나의 공식 series나 만능 AI workflow로 묶지 않는다.
- artifact 개수, 사건 개수, heading 수를 새 고정 기준으로 만들지 않는다.
- 이전 v1의 생생함을 회수한다는 이유로 v2·v3에서 교정한 actor·수치·제안/구현 경계를 되돌리지 않는다.
- 모든 글에 같은 checklist, 같은 결말, 같은 `X가 아니라 Y` 문장 engine을 적용하지 않는다.
- 독립 reviewer의 추천을 사용자 합의나 새 정답으로 올리지 않는다.
- 사실 교정과 공개 경계 외에는 새 v1을 조용히 수정하지 않는다. v2는 사용자 review와 결정 뒤 별도 snapshot으로 만든다.

## 사용자 review에서 결정할 것

1. `current.md`라는 개인 운영 이름을 공개 글의 제목과 개념으로 유지할지
2. AX output-first 재료를 판단 순서 글에 귀속하고 별도 `Output-informed problem selection` 후보를 흡수·재정의할지
3. Self-check v2에서 했다체와 더 개인적인 retrospective 호흡을 다시 시험할지
4. 첫 공개 후보를 독립 판별 글로 보고 다음 shaping을 우선할지, 다섯 편을 같은 깊이로 한 번 더 볼지
