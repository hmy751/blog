# AI self-check 원천 대조

## 가장 큰 교정

post-sync v1의 `회사 중심 → 사용자 중심 → 역할 관계 재구성`은 실제 사건 순서와 맞지 않는다. 당시 작업도 두 답안의 관점 배분보다 조사 workflow와 증명 범위를 다시 배열한 사건에 가깝다.

원자료로 확인한 순서는 다음이다.

```text
첫 종합
회사 직접 자료 → 회사가 중요하게 보는 방향을 판단
사용자·독립 자료 → 현재 문제인지 확인할 빈 곳을 판단
두 결과를 함께 만들되 섞지 않음

반대 방향 과교정
회사 방향을 먼저 확정
→ 그 주변의 미해결 마찰만 나중에 확인
→ 함께 보던 두 판단이 순차 구조로 축소됨

관계 복구
회사 직접 자료 → 회사 방향에 높은 가중치
사용자·독립 자료 → 현재 문제의 해결 상태와 반복 여부 확인
두 판단을 동시에 만들고,
서로 만나는 지점에서 다음 조사 질문을 고름
```

첫 별도 점검의 판정은 유효했다. 문제는 작업을 조율한 AI가 그 판정을 적용하며 기존의 동시 검토 구조를 지우고 반대 방향으로 과교정한 데 있었다. 사용자가 직전 결론이 아니라 앞선 종합과 전체 대화를 다시 보게 했고, 더 넓은 입력을 읽은 두 번째 점검과 main의 재적용 뒤 역할 관계가 복구됐다.

## assignment 장면

- AI는 원본 자료 구역이 보이지 않는 이유를 기존 분류 규칙으로 설명했다.
- 사용자는 재구성 결과가 있다면 바탕 자료의 존재 가능성을 역추적해야 한다고 지적했다.
- 전체 재검색 뒤 한 과제의 누락과 추가 세 곳의 분류가 고쳐졌다.
- 사용자는 두 차례 “AI 관점에서 더 근본적으로” 보라고 요청했다.
- 중간 AI 답변 전문은 남아 있지 않다. 따라서 요청 직후 어떤 provenance 일반론을 말했다고 재구성하지 않는다.
- 후대 보존 발화에서는 AI가 실제 과제 맥락보다 출처 과확정 방지라는 일반 문서화 관점을 너무 강하게 가져왔다고 인정했다.
- 이 수정은 formal self-check의 단독 효과가 아니라 사용자의 직접 정정과 재검색 지시가 만든 결과다.

## forward-bias 장면

- 작업 지침의 `기본은 전진` 문구가 충분히 판단하기 전에 실행으로 가는 경향을 만들었다는 문제를 다뤘다.
- 보존된 사용자 발화에는 같은 전진 방향을 세 차례 멈춘 기록이 있다.
- 사용자는 허용 행동을 `실제 작업 없이 생각만 → 실제 수정 없이 before/after 비교만`으로 계속 좁혔다.
- 결과적으로 전진 기본값을 제거하고 임팩트 있는 행동을 먼저 정한 뒤 근거로 따지는 문구로 바꿨다.
- 각 제동 직전 AI 답변 전문과 총 반복 횟수는 보존되지 않았다.
- 지침 변경 뒤 장기 행동 안정이나 재발 감소도 측정되지 않았다.

## 보호할 문장

- “한쪽으로 기운 판단을 고치다가 반대쪽으로 넘어간 것이다.”
- “결론은 달라졌지만 판단축은 그대로였다.”
- “내가 원한 것은 더 큰 AI 일반론이 아니었다. 방금 결과를 만든 결정 위치로 돌아가는 일이었다.”
- “‘더 근본적으로’를 ‘더 추상적으로’ 읽은 셈이었다.”
- “문제를 설명하는 것과 다음 행동이 달라지는 것은 같은 결과가 아니었다.”
- “self-check가 바꾼 것은 AI를 더 믿게 된 정도가 아니었다. AI의 설명과 행동을 같은 결과로 보지 않게 된 것이었다.”

이 문장들은 공개용 저자 문장이다. 당시 사용자 발화나 AI 답변의 직접 인용으로 표시하지 않는다.

## 독립 판별 글과의 경계

Self-check 글은 왜 main의 판단 자체를 검사 대상으로 옮기는지를 맡는다. 같은 위치가 스스로 빠져나오지 못하면 더 넓은 입력을 보는 별도 판단 위치가 필요해질 수 있다는 연결까지만 둔다.

다음 내용은 독립 판별 글이 소유한다.

- fresh/read-only 조건
- 판별자가 직접 볼 원천
- 문제 이름과 질문을 바꿀 권한
- 판별 출력의 별도 상태
- main의 채택·조정·기각과 재실행
- 별도 판단도 자동 정답이 아니라는 계약

## 공개 경계

- 회사명, 해커톤명, 내부 프로젝트명과 문서 번호를 쓰지 않는다.
- 내부 agent 이름, raw JSONL 이름, session ID를 쓰지 않는다.
- 비공개 사용자 발화 원문과 오탈자를 직접 인용하지 않는다.
- 보존되지 않은 중간 AI 답변을 복원하지 않는다.
- `회사 중심 → 사용자 중심`이라는 원천 불일치 artifact를 쓰지 않는다.
- self-check가 이후 같은 오류를 예방했다고 말하지 않는다.
